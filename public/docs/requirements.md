- 在内容创作模块中要求填写／选择三项：**产品资料／已有内容、写作目的、目标读者**。每项提供小字描述和例子，帮助用户理解。

- **只有平台 × 语言分别生成独立稿件，其他选择合并为创作要求，不继续扩展版本数量。** 例如小红书 + 中文／英文生成两份稿件；小红书／LinkedIn + 中文／英文生成四份。不要融合为跨平台、多语言的一篇稿件。
- 内容格式多选可在同平台、同语言产物内形成多个内容部分，例如长文章和配套短动态；仍保留实际渠道对象的区别。

- 配图和素材可选并提供说明：有上传则结合素材一起创作；未上传／未选用则默认由 Agent 生成所需素材。实际生成工具尚未接入，不能提前声明可用。

## 已确认的 skill 准备与执行方式

先从已有技能、用户参考和公开作者仓库等来源搜集相关 skill，逐份读取正文及必要附属规则，统一比较、筛选和总结。去掉重复、过时和冲突内容，保留来源与版本，整理为基础创作规则及各选项对应的规则片段，再用用户已有文章实际试稿验证。

用户只选择创作选项，不选择 skill。系统按固定映射拼装每份稿件唯一的一套执行规则，例如基础规则 + 小红书规则 + 中文规则 + 风格／格式等已选要求；不让 Agent 临时从多个 skill 中猜选。独立出稿仍只按平台 × 语言，其他配置合并使用。

第一阶段只整理文本创作，视频规则下一阶段补充。该工作方式已确认；目前只完成部分创作技能核查及平台审核候选初筛，全面搜集、统一整合、映射和试稿尚未完成，不恢复开发。

## 已确认：生成后的自动审核

每份平台 × 语言稿件都执行「生成初稿 → 审核一次 → 根据问题修订最终稿」。审核作为创作模块内部一步，不再设独立模块，也不要求用户在初稿与审核之间操作。

审核规则预先搜集、比较和整合，再与平台选项固定绑定；语言与内容格式用于选择适用规则，例如 LinkedIn 动态与原生长文章不能套用同一套篇幅检查。运行时使用已确定的映射，不临时挑选陌生 skill。

审核的具体内容、候选取舍及映射仍待确定。**用户明确要求现在只记录，审核内容确定、公开 skill 搜集、分析整合、平台绑定和试稿验证都留待之后统一执行。** 此前提前发生的只读检索保留于 [平台审核 skill 初筛](平台审核skill初筛.md)，不作为已认可选型，停止继续检索或实施。最终稿可供用户查看、修改和确认；自动审核完成不等于作者批准或平台审核通过，未解决的问题仍须可见。

## 已确认：用户确认后才正式保存

- 生成的内容须由用户确认后才正式保存。初稿、自动审核后的修订稿及生成素材在确认前最多暂存在 tmp 临时记录；自动审核完成不能触发正式保存。
- 用户可在右侧内容查看窗口查看、修改待确认内容。未确认内容不进入正式内容库或待发布清单，不能用后台自动保存或执行日志正文副本绕过这一规则。
- 用户确认后，才将确认的内容和对应素材保存为正式版本。确认保存与确认发布分开，不因此自动发到外部平台。
- 对已有正式内容生成的新修订，同样先暂存；用户确认后再保存新版本，保留原已确认版本。
- tmp 的保留时间、恢复和清理方式后续统一确定，本次不清理任何已有数据，也不实现该功能。

## 一次内容工作的完整链路

1. **创作**：根据用户提供的主题、重点和资料生成所选平台／语言初稿，按平台绑定的规则自动审核一次，再按结果修订最终稿。语言版本分别表达，不要求逐字翻译。必要时读取或补查资料并保留来源；用户可在工作台右侧查看正文、按段修改或提交修订意见。确认前最多暂存在 tmp，用户确认后才正式保存；已有正式版本保留。无需独立研究或审查关卡；审核具体内容和改稿交互继续按讨论结果细化。
2. **发布**：把指定语言、渠道与已批准版本绑定，展示最终预览，通过该渠道实际可用的接口或浏览器流程提交，记录真实文章/帖子链接和执行状态。
3. **反馈分析**：暂留空，后续再设计，本轮不实现采集、统计或分析功能。

## 两种交付物

**Launch kit 工作版**：含内容目录、受众和角度、双语正文、各渠道衍生稿、封面/配图、事实来源、审查问题、修改意见、发布说明与计划。它是用户迭代的主要材料。

**Launch copy 发布版**：从同一内容记录输出已经确认的版本，图片在前，每条内容有清楚标题，正文可直接复制；依项目 skill，仅保留必要的简短 Posting 提示。不得把内部审查记录混入公开正文。

两个文件应由同一份结构化内容产生，避免修订时只更新其中一份。中英文可以各自导出，也可以导出双语合订版本。DOCX 是正式交付格式之一；工作台页面须同时提供舒适的阅读与编辑体验。

## 发布与反馈必须区分的对象

五个平台的最新只读核查与工作台调整建议见 [发布接入与工作台调整记录](发布接入与工作台调整记录.md)。接入需区分平台与内容类型；API、浏览器辅助和人工交接的最终选型尚未确定，不能承诺五个平台全部自动发布。本轮没有账号授权、试发或界面变更。

本节发布对象的区分仍适用于当前设计；反馈相关内容和历史接入核查仅供后续参考，不视为当前已确定的反馈方案或实施要求。

LinkedIn 原生长文章与 LinkedIn feed post 是两种产出。把一个文章链接分享到动态，不等于创建 LinkedIn 原生长文章。渠道适配器必须声明它支持哪一种操作，不能仅因某工具写着支持 LinkedIn 就认为支持全部文章功能。

反馈按文章或帖子分别记录。阅读数、曝光、点击、点赞、评论、转发和 GitHub 变化不混用；无法取得的数据标记为未获取，不能填 0。公开可见评论与只有作者能查看的统计权限分开处理。

本次官方资料核查发现：

- LinkedIn [Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api?view=li-lms-2026-09) 的 article 是附带 source URL 的链接卡片。本次未找到可依赖的公开 Pulse 长文章正文创建 API；[原生文章编辑器](https://www.linkedin.com/help/linkedin/answer/a521657) 是已确认的长文入口。
- Buffer 可以复用动态发布；[官方 API 说明](https://support.buffer.com/en-us/articles/what-is-buffers-api-GtIYIQilz5) 把指标能力列为实验功能，公共 API 暂不支持评论读取/回复。
- [Typefully 分析说明](https://support.typefully.com/en/articles/8718148-analytics-page-metrics) 当前仅支持 X，不能把它当成现成的 LinkedIn 反馈统计来源。
