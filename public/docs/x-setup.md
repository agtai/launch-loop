# X 账号连接与发布指南

更新：2026-09-26。

**当前还没有完成真实 X 账号授权、图片上传、发帖和线上显示的验收。** 工作台已实现连接与发布流程，并通过隔离测试；测试使用的是合成账号和平台替身，不能据此认为你的账号已经可用。

请先由项目负责人或管理员准备 X 开发者应用、所需权限、可用 API 额度和授权回调地址。普通操作者不需要处理这些技术配置，也不要把密码、Client Secret、访问令牌或完整授权回调链接贴进聊天、工单、截图或项目文件。

## 普通操作者怎么使用

### 1. 等负责人完成配置

如果发布页显示“尚未配置 X 官方应用”，先联系负责人。登录 X 网页或购买 X Premium，不代表应用已经获得 API 发布权限。API 调用可能另外收费；工作台不会代为购买额度或开启自动充值。

### 2. 连接自己的发布账号

打开工作台的“发布”页面，在 X 区域点击“连接 X 账号”。页面会跳转到 X，由你登录并确认授权。完成后应回到本机工作台；请核对显示的姓名和 `@用户名`，确认是准备发布的账号。

如果显示授权过期或权限不足，按提示重新连接，或请负责人检查配置。服务重启后需要重新授权。连接成功只表示已核对账号和授权返回的权限；图片上传、发帖权限和额度仍要以实际平台响应为准。

### 3. 核对一份具体内容

先在创作页检查稿件并“确认保存”，再到发布页选择作品、正式版本、语言，以及普通帖子或整条串帖。未经确认保存的临时稿不会进入发布选择。

普通帖子首版支持一张图片，串帖首版支持首帖一张图片。带图时，先在创作页检查图片是否清楚、是否符合正文、替代文字是否准确，并如实保留 AI 生成来源。后台配图能否自动生成，以创作页的实际能力检查和生成结果为准；上传图片可用不等于已经能自动生成图片。

点击“核对发布预览”，逐条查看文字、顺序、字数和图片。一次只发布所选语言和内容对象；同时生成普通帖子与串帖，不会把两者一起发布。

### 4. 由你决定是否实际发布

**确认保存和查看预览都不会发帖。** 最后的发布确认会上传选中的图片并调用 X 发帖接口，可能产生 API 费用。只有当你核对了具体账号、正式版本、全部文字和图片，并决定实际发布时，才勾选确认并点击“确认发布到 X”。本次开发工作没有替你作出这项决定。

预览十分钟后失效。账号、作品版本、文字顺序或图片变化后，要重新预览和确认。

### 5. 遇到中断，先看发布记录

| 页面状态 | 处理方式 |
|---|---|
| 已发布 | 查看每条对应的实际发布结果，并到 X 检查文字、图片和串帖阅读顺序 |
| 部分已发布 | 前面成功的帖子会保留；使用原记录的“核对已发部分并准备续发”，核对新的续发预览后再确认 |
| 结果未知 | 请求可能已被 X 接收，先到 X 核对；不要新建相同帖子或反复点击发布。缺少可核对的平台结果时，工作台会继续阻止自动重发 |
| 发布失败 | 查看具体原因。权限、额度或限流问题交给负责人处理；处理后仍需重新预览、明确确认 |
| 正在取消 | 停止的是后续步骤；正在进行的请求仍可能成功，等待记录更新后再判断 |

工作台不会自动删除已发布的部分，也不会为了回滚而删除后重发。恢复旧备份不会触发发布，也不会抹去当前已有的成功或未知记录。

## 管理员配置

以下配置只在负责运行工作台的电脑上进行，不需要操作者在网页中输入密钥。

### 应用与额度

在 [X Developer Console](https://console.x.com/) 核查自己的开发者应用是否获准使用官方 API，并启用 OAuth 2.0 用户授权。确认应用类型是公开客户端还是机密客户端，以及账号可用额度和消费限制。当前官方采用按使用付费；具体费用、余额、优惠和端点资格以控制台为准。[官方计费说明](https://docs.x.com/x-api/getting-started/pricing)

工作台固定请求以下权限，并以 token 实际返回的权限为准：

| 权限 | 用途 |
|---|---|
| `tweet.read` | 续发前核对已发布帖子 |
| `tweet.write` | 创建普通帖子及本任务内的逐回复串帖 |
| `users.read` | 读取并核对授权账号 |
| `media.write` | 上传图片和写入图片替代文字 |

这些权限用于本版的标准帖子与图片流程。本版不请求 `offline.access`，不自动刷新 token；默认授权有效期约两小时，实际以平台返回值为准。[官方 OAuth 2.0 PKCE 文档](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code)

### 回调地址

本版要求注册一个精确的 HTTPS 地址，路径为 `/api/x/callback`。例如 `https://callback.example.invalid/api/x/callback` 只是格式示例，管理员必须换成自己实际控制和配置的地址。地址不能包含用户名、密码、查询参数或片段；应用登记的地址与 `X_REDIRECT_URI` 必须完全一致。

HTTPS 代理只开放这一个回调路径，转发到当前工作台的 `http://127.0.0.1:<实际端口>/api/x/callback`，保留回调查询参数，并将上游 Host 设置为 `127.0.0.1:<实际端口>`（或工作台允许的同端口 localhost）。不要转发整个工作台、内容 API 或数据目录；工作台本身仍只监听本机。代理不要记录包含授权码的完整回调查询串。工作台不会代为创建公网域名或隧道。

### 启动进程的环境变量

| 环境变量 | 配置要求 |
|---|---|
| `X_CLIENT_ID` | X 应用的 OAuth 2.0 Client ID，必填 |
| `X_REDIRECT_URI` | 已登记的完整 HTTPS 回调地址，必填 |
| `X_CLIENT_SECRET` | 机密客户端必填；公开客户端不设置 |

通过管理员认可的安全方式，将变量注入启动工作台的进程环境。不要把实际值写入 Git、共享脚本、运营备份或聊天；也不要使用会把 secret 留在命令历史中的示例命令。工作台直接读取进程环境，单独建立 `.env` 文件不会被自动读取。仅给机密客户端填 Client ID，可能使页面认为基本配置已提供，但正式 token 交换仍会被 X 拒绝。

修改环境后，按项目 README 的方式停止并重新启动**本工作目录对应的服务**，保持既定独立端口和数据目录，不影响其他工作台实例。操作者随后从发布页重新连接。

### 核对流程

本版采用 OAuth Authorization Code + S256 PKCE；通过 `GET /2/users/me` 读取真实账号。token、授权 state、PKCE verifier 和预览确认凭证仅保存在本次服务内存，不进入内容数据库或备份。下一位负责人在自己的电脑上应使用自己的应用配置和正式授权。

发布使用 `POST /2/tweets`；串帖仅回复本次计划中的前一条。图片使用 `POST /2/media/upload`，核对媒体处理状态和有效期后设置替代文字。AI 生成图片按素材来源设置 `made_with_ai` 披露字段。[发帖接口](https://docs.x.com/x-api/posts/create-post)、[图片上传](https://docs.x.com/x-api/media/upload-media)、[媒体元数据](https://docs.x.com/x-api/media/create-media-metadata)

遇到 401 检查授权是否失效，403 检查应用与账号权限，402 检查 API 额度，429 检查限流窗口。不要通过反复发布试探权限或额度；已提交但结果未知的请求必须先核对。[官方限流说明](https://docs.x.com/x-api/fundamentals/rate-limits)

真实验收应分别记录：账号授权是否成功、图片上传是否成功、每条帖子是否取得真实结果、X 上的文字图片及串帖是否正确显示。授权或测试通过不能替代操作者对具体内容的最终发布确认。
