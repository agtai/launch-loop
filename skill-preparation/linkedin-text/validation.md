## 方法和可比性

使用用户 s1a-launch-kit、launch-copy 的 LinkedIn 两节，与产品仓库固定 commit `0f0b4c9eca03127875cfdf0d941fbd22c16478a4` 的 README、docs/skills、docs/benchmarks、CHANGELOG 四份全文。两组使用完全相同的 `inputs/trial-input.json`（SHA-256 `ac34253788598a16a32dc25265d317dc98799401bc85ba3975d8ffe8bebf16eb`），不是从原工作区复制旧运行产物。

旧组使用本分支未改动的 `resolveTextRules` 与 `text-v1.0.0`，每语言各生成→审核一次→修订。新组使用固定候选组合与同一输入，先母稿→平台稿→本地化，再每稿审核一次，集合齐后统一修订。模型均 `gpt-6-astra`、推理 `xhigh`，CLI使用已有ChatGPT认证，temperature 未设置、seed不可用；差异主要是规则和编排，不能宣称严格随机对照或普遍质量提升。

真实调用使用新 worktree 内未修改的 `server/generation-runner.mjs` 导出函数，经独立 tmp 子目录与 Windows Job Object 运行，未启动任何工作台服务。有限执行脚本为 `tmp/skill-deepening/trial.mjs`、`candidate-trial.mjs`，提示只经 stdin，事件、schema、输出和诊断都在 tmp。每次成功需退出0、实际 `turn.completed` 和有效 JSON；连接探针成功不算正文试稿成功。没有修复／借用123服务，没有访问账号联调状态。

schema 为技能实验做了简化：正文作为一个 body 字符串；母稿保留事实、术语台账，平台及本地化有段落 claimAlignment。它没有模拟现有 HTTP schema 或完整未来数据契约。审核位置的精确引用可做外部验证，拟议文档/block id、完整序列化字段和 UI 仍需后续接入。

两组均明确 text-only 且仅交配图 brief，这是相同的本轮范围约束；旧规则本身的自动配图要求未被当成已完成。正文与图片实际视觉检验、线上计数或发布不在这个实验中。
