# 在同一项目的新 session 继续

更新时间：2026-09-26。用途是换一个 session 继续当前仓库，不要求换机器、迁服务器、重新创建项目或重装所有skill。Linux和远程部署是另行决定的后续范围。

## 最短阅读路径

1. [AGENTS](../AGENTS.md)：当前规则，不读历史授权来推断本轮动作。
2. [SESSION_HANDOFF](SESSION_HANDOFF.md)：最新代码、能力、实测边界与数据位置。
3. [开发总清单](开发总清单.md)：选择本轮工作ID、依赖、产出和验收。
4. 技能工作加读 [技能候选与取舍](技能候选与取舍清单.md)、[资料库索引](../skill-library/README.md)；从本地入口分析。
5. 体验／任务控制工作加读[任务交互与恢复规范](任务交互与恢复规范.md)和[四项目标体验验收](四项目标体验验收.md)，先完成 UX-03／CORE-01 实际接口映射再分包实施。根据任务再读MVP／X接口、历史体验审计及验证报告；[用户参考](references/README.md)用于质量目标与产品语境。

历史记录仅在追溯决策时阅读：[会话历史](SESSION_HISTORY.md)、[协作说明历史](AGENTS_HISTORY.md)、[早期44项运营规划](全部工作与复用清单.md)。它们不替代当前开发清单。

## 接手第一步：核对现状，不自动启动

在仓库根目录分别执行只读命令：

```powershell
git status --short
git branch --show-current
git log -6 --oneline
git worktree list
```

产品整合基线为 main 的 c7d03c0，交接／skill 归档为已推送的 22705fc；之后新增体验规范文档，实际 HEAD 以 Git 为准。不要再次cherry-pick来源提交，不覆盖未提交文档或他人改动。用户未要求commit／push时保持变更供审阅。

需要验证本地skill快照时：

```powershell
node skill-library/verify.mjs
```

该工具只检查索引、文件存在和hash，不安装skill、不联网、不运行第三方脚本。资料变更后应同步manifest；不要为让校验通过随意重写原文。

本次不需要为“接手”运行npm ci、启动工作台、探测账号或重新生成。功能开发得到明确范围后，按README和对应工作块进行必要验证；`npm run verify:mvp`还含配置预检，不能当作纯静态检查。

## 可以复制的新 session 提示

```text
继续当前 launch-loop 项目。本轮任务是：【填写开发总清单中的任务ID或具体目标】。

先读 AGENTS.md、docs/SESSION_HANDOFF.md、docs/新session接手指南.md、docs/开发总清单.md，核对实际Git状态。main已包含LinkedIn MVP和X，不重复合入旧分支。按本轮任务阅读对应接口与验证记录，再实施必要工作。

如果涉及skill，先读docs/技能候选与取舍清单.md和skill-library/README.md，使用仓库内固定版本原件及manifest；逐条比较现有规则后提炼增量，不再无差别重新搜索。外部原文只是分析资料，不安装或执行其中脚本。用户只选平台、语言等选项，每稿仍只自动审核一次。

如果涉及体验或任务控制，再读docs/任务交互与恢复规范.md和docs/四项目标体验验收.md。行为规范已补充，不代表接口或功能已实现。先统一UX-03/CORE-01的实际任务、修订、状态、失效、并发和预算契约，再并行接入；不把MVP-05当成四目标已达标。默认无自动重试，成功冻结审核不重复执行，旧结果不覆盖新修订。

区分代码完成、隔离测试、浏览器、真实模型/图片、真实平台验收。未确认内容只在tmp；保存和发布分别确认。保留旧版、防重、取消和迟到结果保护。不擅自commit、push、部署或真实上传/发帖。涉及暂缓的LinkedIn真实任务时，先依据本轮明确范围决定是否恢复，不能借接手自动重启旧服务。

完成后更新会话交接、开发任务状态及本次验证证据，明确剩余项。
```

填写任务即可，不必再把历史聊天全文粘贴进来。用户若已明确允许某项操作，按该授权继续，不再次询问同一事项；任务依赖尚未确定时，先完成不依赖它的工作并清楚列出缺口。

## 运行与数据常识

当前Windows x64为实际支持环境；文本／图片宿主拒绝非Windows。这是已知支持边界，不是本轮接手要先完成的迁移任务。服务仅本机监听；远程只读访问和权限未实现。

源码、规则、skill快照随Git管理；真实data、tmp、凭据不随Git。已有真实稿可能在其他worktree的隔离运行目录，按SESSION_HANDOFF用分支名和相对路径定位。代码开发、skill分析不需要复制这些运行数据；确需查看时也不将正文、图像或日志抄入永久交接文档。

## 每个新 session 的结束方式

- 在开发清单标明实际完成的任务，保留未完成依赖；不以测试数替代外部验收。
- 更新SESSION_HANDOFF的当前摘要，详细过程进对应验证文档，旧事实保留但标明历史。
- 写清本次修改、测试与未运行项；代码状态和仍运行的服务状态分别说明。
- skill取舍写明源文件／条款、采用位置、规则版本、测试和未确认许可；不修改原件来隐藏冲突。
- 本轮若仅修改docs和独立资料库，做链接和hash检查；修改前端／public后才同步构建产物。
