# 第二阶段执行与发布接口

2026-09-23。复用第一阶段的 [内容存储接口](内容存储接口.md) 和 [text-v1.0.0](../rules/text/v1/README.md)。请求／响应类型见 [content-types.ts](../src/content-types.ts)，任务字段和路由表见 [第二阶段接口与分工](第二阶段接口与分工.md)。实现和测试通过不代表真实外部服务已验收，实际证据以 [验证记录](验证记录.md) 为准。

## 创作与执行

2026-09-24 第三轮实测更新：实际界面触发的精简真实材料任务已完成中英文各初稿／一次审核／修订；真实局部改稿与接受、源稿变化后拒绝迟到结果、取消均通过。未确认稿件留在tmp，配图仍未连接。任务ID与失败证据见[最新验证](验证记录.md)，下文早期超时不代表目前仍无正文。规则保持text-v1.0.0。

界面直接进入创作，产品资料／已有内容、写作目的、目标读者必填。LinkedIn、中英文、普通动态是可见可修改的本阶段预设。平台 × 语言决定稿件数量，其余选择合并为要求；其他四平台、Pulse 与未适配格式明确拒绝执行，不能套用 LinkedIn 规则。用户不选择 skill。

`POST /api/generation/jobs` 接收客户端 UUID requestId、name、brief、uploads 与 options。同键同输入返回原任务，异输入返回409；已结束任务重新生成必须用新 requestId。GET任务轮询；取消通过 POST任务的cancel接口，不能通过断开浏览器假定任务已取消。

支持真正读取 UTF-8 TXT／MD／Markdown 和选用 PNG／JPEG。文件名不是来源内容；执行保存来源文字、hash和规则快照。PDF、DOCX、URL自动抓取尚未支持，需明确报错。单素材4MiB、内容请求8MiB，另有文字总量与图片数量检查。图片提交给模型作为图像输入；没有上传图片时返回“自动配图未连接”，不能把图片提示词当已生成图片。

每种语言串行执行初稿、一次审核、修订三次模型调用。审核针对实际正文引用片段并提出问题；未解决项在最终稿保留。独立任务目录包含提示、schema、实际输出、完成事件及诊断，全部位于 `dataDir/tmp/generation/`；待确认稿及选用素材位于 `dataDir/tmp/content/`。这些目录不进入正式数据库正文或JSON备份，也不自动清理。

执行器通过结构化 argv 和 stdin 调用当前已登录的 Codex CLI，不使用 shell 拼接正文；模型为Astra Xhigh，单次调用上限300秒。CLI临时自定义provider关闭WebSocket、保持ChatGPT认证，不设置base_url、API key或token，不修改用户全局配置。[官方认证说明](https://learn.chatgpt.com/docs/auth#alternative-model-providers)支持自定义provider使用ChatGPT登录，[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)列出supports_websockets。2026-09-24 已通过现有代理完成22.4秒最小真实调用，以及50.5秒同生产document schema的精简真实资料调用；原完整资料的工作台任务仍触发300秒超时，stderr无网络错误证据，不能把最小成功等同完整链路成功，或把未定位超时都归为网络问题。各次任务见最新[验证记录](验证记录.md)。

第三轮补充执行边界：每次调用只执行 `payload.task` 当前阶段，完整初稿／一次审核／修订由服务编排。规则中的全流程、保存确认和配图约束不能被当成文本模型调用其他工具的许可。文本执行器继续禁用图片和其他工具；后台图片是单独待接入能力，不以文本提示或会话出图替代。

Windows可选 `Start-Workbench.ps1 -UseSystemProxy`，仅本次子进程复用当前用户启用的无凭据手工系统代理；已存在的进程HTTP(S)/ALL_PROXY优先，添加本机回环NO_PROXY，父环境随后恢复。PAC、含凭据和不明确映射明确拒绝，不更改全局配置。选中Node声明支持时加入 `--use-env-proxy`，旧Node明确提示原生fetch的限制；仅有ALL_PROXY时不替Node猜测HTTP(S)映射。参数不影响已启动服务，需用本目录停止脚本正常停止后重启。无该参数保持原启动行为。

Windows使用Job Object约束本次CLI及其子进程；超时、取消、服务关闭或父进程异常退出只终止本任务拥有的进程。必须收到本次有效完成事件并校验本次输出，不能用旧文件补结果。非终止的CLI重连／功能警告不单独视为工具调用或成功；真实turn.completed、退出码和schema仍须同时满足。重启将未完成任务标为interrupted，不自动续跑。

`POST /api/generation/modifications` 要求源tmpId、revision、documentId、blockId、起止位置、选中文字和修改意见。服务器复核选区，保留其他段落及选区外字符，只返回独立修改提案。调用任务accept接口再次检查源revision，接受后派生新的可编辑tmp；接受建议仍不是确认保存。修改期间源稿被手工改动则拒绝迟到结果。现有正式版本经revise进入tmp；正式保存依旧仅使用内容confirm接口，产生新版本并保留旧版。

修改任务还需能找到对应原生成任务的完整规则选项及来源。仅恢复正式备份而没有原执行tmp时，无法恢复这组执行配置，应按提示重新生成；不得凭规则hash猜选项。恢复使旧tmp过期，保留可读，显式fork后才可继续。

## LinkedIn账号与配置

只实现个人账号PUBLIC普通feed动态，最多一张PNG／JPEG；链接卡片不是原生Pulse文章。工作台目前没有已验证的用户应用授权或真实发帖证据。

服务端环境配置 `LINKEDIN_CLIENT_ID`、`LINKEDIN_CLIENT_SECRET`、`LINKEDIN_REDIRECT_URI`。API版本缺省 `202609`，可通过 `LINKEDIN_API_VERSION` 指定YYYYMM。默认请求 `openid profile w_member_social`；应用需已有OIDC与Share on LinkedIn产品授权。只有应用已获准额外受限读取权限时才将 `r_member_social` 加入 `LINKEDIN_SCOPES`。

不要在聊天中粘贴密钥，也不要写入仓库、浏览器存储或运营备份。环境由操作者在本机安全设置；OAuth token只存在服务内存，服务重启后重新授权。已有LinkedIn网页登录不能替代API授权。

注册的回调必须HTTPS，准确匹配开发者门户地址，路径为 `/api/linkedin/callback`，无query或fragment。应用仍只监听127.0.0.1 HTTP；若配置HTTPS回调代理，只代理该回调路径，并将Host改写为 `127.0.0.1:<本机端口>`，不得公开整个工作台API。本项目不自动创建公网隧道或购买服务。

连接start接口返回LinkedIn正式授权URL，可传 `{locale:'zh'|'en'}`，空对象保持兼容。随机state一次性且10分钟过期，绑定发起请求的已验证本机origin和界面语言；callback验证state、换取token并读取userinfo。只有平台实际返回且合法解析的scope才作为已授权scope（支持官方注明的URL编码），缺失时不猜测成功。连接状态为unconfigured、disconnected、connected、missing_permissions或expired，具体以接口message为准；后续401／403同步禁用发布，reconcile的401也会标记会话失效并保留unknown记录。

成功HTTP回调303返回绑定本机origin的 `/#publishing?linkedin=connected`，不携带code、state或token。前端只借标记选择发布页，随后GET实际连接状态，并移除hash；失败返回固定中英文HTML、no-store/no-referrer、严格CSP和本机 `/#publishing` 链接，不回显平台原始错误。客户端不能指定任意return URL。实际应用和只公开回调路径的配置步骤见[LinkedIn授权配置](LinkedIn授权配置.md)；文档范例不是已部署HTTPS资源的证据。

## 预览、确认与发布

未确认保存的tmp不能提交预览。preview从指定正式itemId/versionId读取同版本正文与素材，验证账号及素材字节hash。正文由非空title和blocks以空行拼接，postingNote不发布；保守限制3000 UTF-16字符，不自动截断。非图片资料不上传为附件，多图明确拒绝。

preview在内存中绑定版本、正文／素材hash、账号、授权会话、恢复epoch及10分钟期限。执行要求 `confirmed:true` 和该预览的随机confirmationToken；后端重新校验，不依赖前端隐藏按钮。更换账号、恢复备份、版本／素材变化或过期后必须重新预览确认。保存版本不会调用执行接口。

发起网络请求前，事务持久化submitting并按账号＋最终正文／图片hash防重。同预览重复请求返回同记录；相同内容处于submitting、published或unknown时，新预览也不能绕过。图片通过官方Images初始化及PUT，再通过Posts创建。只有201及有效平台URN才标为published，保存真实ID和据此形成的URL。

网络中断、5xx、409或201缺失有效ID均为unknown；绝不自动重发。明确拒绝的4xx记failed，修复后仍须新建预览并重新确认。重启遗留submitting转unknown。已有平台ID且有受限读取权限时可调用reconcile只读核对；无ID则需到平台人工核对，不能凭本地错误推断未发出。

## 存储与恢复

发布记录与内容使用同一SQLite，新增显式迁移；记录仅保存版本指针、hash、状态、平台ID等元数据，不保存正文或凭据。Windows同数据目录仅允许一个服务实例，由操作系统命名管道租约防止第二实例误判活跃提交已中断。

备份协议继续为 `app: "content-workbench-local"`、`version: 1`，新增可选 `publishing: {schemaVersion:1,records:[...]}`。旧备份没有该扩展时保留已有发布事实；新备份采用合并，不能通过恢复删除已发布／未知记录或降低其防重状态。恢复中的submitting转unknown，不发起网络请求；活跃发布期间拒绝恢复。恢复前快照和完整事务保留。

每条备份记录使用固定4096字节包络，padding仅空格，用于在联网前预留结果元数据容量。完整备份仍最多16MiB，发布前做容量检查，不能发出后因其他本地写入挤占空间而丢失结果。旧程序不识别新增扩展，需用当前版本恢复。JSON备份不包含tmp、OAuth token或client secret。

以下页面于2026-09-23核查；它们证明公开协议，不证明用户账号已获权：

发布自动测试使用合成fetch与临时数据，不调用真实账号。真实OAuth、平台图片处理及显示、创建和已知ID核对仍需合法配置与对应授权；本轮开发指令没有授权真实发帖。
