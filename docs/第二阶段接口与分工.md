## 生成与修改契约

沿用 `ContentBrief`、`ContentUploadInput` 和 `ContentTmp`。UI 可见且可修改的试运行预设是 LinkedIn、zh/en、short_post，不是全局默认。材料和参考项支持文字、实际上传；URL 未读取成功必须报明原因，不将文件名／URL 当已读内容。

- `GET /api/generation/capabilities` → `{text:{status,message},image:{status,message},materials:{extensions}}`。text 为 available/unavailable/unknown；image 为 available/unconnected。不可凭 CLI 文件存在声明认证成功。
- `POST /api/generation/jobs` 输入 `{requestId,name,brief,uploads,options}` → 202 `{job}`。requestId 为客户端 UUID，同键同输入返回同任务，异输入409。options 使用规则解析器的显式 `authorIdentities/styles/depths/project/terminology/referenceMode`；平台、语言、格式来自 brief，assetMode 从选用图片推导。自由文字仍在 brief，不猜枚举。
- `GET /api/generation/jobs` → `{items:GenerationJob[]}`；`GET /api/generation/jobs/:id` → `{job}`。
- `POST /api/generation/jobs/:id/cancel` 输入 `{}` → `{job}`。取消不复用旧成功输出、不自动重启模型。
- `POST /api/generation/modifications` 输入 `{requestId,tmpId,revision,selection:{documentId,blockId,start,end,text},instruction}` → 202 `{job}`。只改选中范围；新任务派生新 tmp，保留其他块及选择外字符。原 tmp 不被后台覆盖。
- `POST /api/generation/jobs/:id/accept` 输入 `{sourceRevision}` → `{item:ContentTmp}`。只适用于完成的修改建议；重新核对源 tmp/revision，源稿期间有修改则409。接纳建议不等于正式保存。

GenerationJob：`{id,requestId,kind:'generation'|'modification',status:'queued'|'running'|'completed'|'failed'|'cancelling'|'cancelled'|'interrupted',stage,createdAt,updatedAt,error:string|null,source:{tmpId,revision}|null,variants:GenerationVariant[]}`。

GenerationVariant：`{platform,language,tmpId:string|null,status,stage,error:string|null,assetStatus:'uploaded'|'unconnected'|'generating'|'ready'|'failed',unresolved:string[]}`。stage 为 queued/reading/generating/reviewing/revising/completed/failed/cancelled/interrupted。任务完成表示文本流程完成；自动配图缺口由 assetStatus 和明确提示保留，不能假装全套图文已完成。

服务工厂：`createGenerationService({content,dataDir,...testOnlyOptions})`，提供 capabilities/create/get/list/cancel/modify/accept/close。`serveGeneration(req,res,pathname,service,{readBody,json})` 独立路由。所有正文、提示、审核和子进程输出位于 dataDir/tmp；普通测试注入替身，真实生成由主 Agent 用实际界面单独验收。服务关闭等待受控子进程退出；异常父进程退出也不留下继续运行的模型进程。

## 发布契约

仅 LinkedIn feed，个人账号。本阶段图片数量／格式以适配器实际支持为准，超出明确拒绝。五个平台保持一致选项，其他平台、Pulse 未适配。

- `GET /api/linkedin/connection` → `{connection}`，包括 status、message、account（id/name/urn 或null）、scopes、canPublish、config（configured/clientId/redirectUri/apiVersion/missing）。不得返回 secret/token。
- `POST /api/linkedin/connection/start` 输入 `{}` → `{authorizationUrl}`，正式 OAuth；`GET /api/linkedin/callback` 仅 OAuth 回调，必须验证一次性 state。`DELETE /api/linkedin/connection` 断开。配置通过服务端环境或安全本地方式；不要求聊天粘贴密钥，不存浏览器或备份。
- `POST /api/publishing/previews` 输入 `{itemId,versionId,accountId}` → `{preview}`。preview 包含 id、itemId/versionId/accountId/accountName、language、body、assets（含版本内下载 url）、contentHash、confirmationToken、expiresAt、warnings。仅从正式版本取正文和素材。
- `POST /api/publishing/execute` 输入 `{previewId,confirmationToken,confirmed:true}` → 202 `{record}`。后端再次校验版本、素材 hash、账号及授权会话，确认一次使用；重复请求返回同一记录，不再发帖。恢复或换账号使旧预览无效。
- `GET /api/publishing/records` → `{items}`；`GET /api/publishing/records/:id` → `{record}`；`POST /api/publishing/records/:id/reconcile` 输入 `{}` 只查询已知平台 ID，不自动重发未知结果。
- PublishingRecord 至少包括 id/itemId/versionId/accountId/accountName/language/contentHash、status（submitting/published/failed/unknown）、platformId/url（未知null）、createdAt/updatedAt/error。不复制正文到日志。

发布存储使用同一 SQLite，提供 exportAll/validateBackup/restore，主 Agent 在原恢复事务内调用；备份扩展为可选 publishing，旧备份不删新发布记录。发布事实采取合并保留策略，已发布／未知记录和防重约束不能被旧备份清除；恢复绝不触发发布。远程提交前持久化 submitting，重启转为unknown，不能自动重试。密钥与 OAuth token 不进运营备份。

发布子任务提供 `createPublishingStore(db,{snapshot,checkBackupSize,content})`、`createLinkedInService(...)` 与 `servePublishing(...)`；精确导出签名在交付时同步主 Agent。主 Agent 负责最后统一代码与类型。

## 本轮验收边界与结果

实际界面触发 Codex 中英生成、各一次审核和修订、局部修改；隔离库验证手工修改、暂存、确认、版本、冲突、恢复、失败、取消和重启。真实配图若无已授权官方后端入口则明确未连接，上传路径仍可用。发布使用本地替身验证协议与保护，真实 OAuth／发布没有条件或授权时列待验收，不冒充完成完整 MVP。运行 npm ci/build/test，同步 dist，不自行 commit/push。

以上为验收目标。最终本地72项自动测试通过，浏览器的上传／看稿／手动编辑／独立确认保存／保留旧版／发布选择与恢复保护已验证。两次真实生成在首个中文初稿的网络连接阶段超时，因此真实双语三阶段和Agent局部改稿仍未验收；浏览器后续存储验证使用第一阶段已有真实试稿，明确标注来源，不能代替本轮模型产出。自动配图、实际LinkedIn授权和发帖亦未验证，详见[验证记录](验证记录.md)。
