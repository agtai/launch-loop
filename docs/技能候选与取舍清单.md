# 技能候选与取舍清单

更新：2026-09-26。面向同项目新session，汇总前轮已采纳来源和新发现的Jiuwen Hub候选。**本轮完成来源归档与已有结论整理，没有修改生产规则，也没有执行原包或重新试稿。** 每条名称直达仓库本地原文；来源、版本、许可和hash见[资料库](../skill-library/README.md)及两个manifest。

## 当前执行方式与后续目标

当前LinkedIn使用[生产v2](../rules/text/v2/README.md)，X使用[固定规则](../rules/x/catalog.mjs)及[配图规则](../rules/x-images/v1/catalog.mjs)。两平台各自走母稿→平台改写→本地化→每稿一次审核→修订；跨平台单母稿是[CORE-01／02](开发总清单.md)待办。候选包[0.2.1](../skill-preparation/linkedin-text/SKILL.md)作为已集成来源保留，不再误标为整个项目尚未接入。

用户只选平台、语言、格式等创作选项；我们整理基础／平台／本地化／视觉／审核规则，固定映射组成每稿完整指令。新增来源只提炼有效增量，不让执行器临时搜索几十个skill猜选，不把团队技能的多个角色和轮次原样搬入。

## 来源、完整性与阅读深度

- GitHub原件固定commit；已知旧版本与原研究保持一致。xhs-note-compliance和x-mentor本轮重新取得时固定当前实际commit，归档不代表已加入生产规则。
- Jiuwen版本来自此前公共目录，并在本轮通过公开版本／artifact接口核对包hash后取回；Hub发布者不自动等于原作者，上游线索及未证实项分开记录。不是根据网站标题推断包内功能。
- 本机shuorenhua按字节复制；用户s1a继续引用已有原件。历史Word和笔记仍在docs/references，不复制到候选原件目录。
- 正文、必要脚本和参考已归档，但**不是全部208份Hub文件／大型提示库都完成逐行语义审查**。部分取舍来自此前实读，额外附属文件只是本轮收齐，后续按缺口阅读。
- 省略的宣传／大参考图、原包未附的服务／依赖、坏相对链接在manifest中记录。原文不篡改，许可未知不推定可公开再分发；只有许可声明与附有LICENSE原文也要分清。

## 怎样进入下一轮工作

| 工作 | 本轮之后要产出的东西 | 验收重点 |
|---|---|---|
| SKILL-01 逐条取舍 | 先看现有规则缺什么，再优先对比repurposer、多平台一致性、视觉brief、图片后端；补本地化／技术审核 | 每条记录源文件／条款、保留／改写／舍弃、理由、平台与阶段；去重复与冲突，不重写所有现有规则 |
| SKILL-02 增量接入 | 版本化短规则、选项映射、来源和兼容说明 | 用户无需选skill；一次审核；保留事实限定、tmp、图文绑定及局改保护；保留可回溯的旧规则 |
| QUALITY-01 质量验证 | 多资料、目的、读者的留出样例及前后对照；模型调用按明确范围执行 | 检查真实事实误差、自然审核漏报、双语一致性与改稿保真；无问题可不改；不以AI分数代替人工质量判断 |

优先四项可与UI或平台账号准备并行分析。生产接入涉及共同母稿／状态模型时先和CORE-01、UX-03对齐，避免两条流程各自扩张。完整任务依赖见[开发总清单](开发总清单.md)。

## 采用记录格式

新增采用记录至少写：

| 字段 | 内容 |
|---|---|
| 来源 | manifest ID、固定版本、文件路径／标题，必要时短摘录 |
| 本项目缺口 | 当前生产规则缺少或冲突的具体行为 |
| 取舍 | 保留／改写／舍弃及理由，不只写“融合” |
| 适用范围 | 母稿／平台／格式／语言／视觉／审核，映射到用户哪个选择 |
| 实现 | 本项目派生规则路径、版本、旧稿兼容与回退说明 |
| 验证 | 隔离边界、真实留出、人工判断及未验项，分别留证 |
| 权利与依赖 | 许可证据、署名要求、脚本／外部服务依赖和未决项 |

实际采用矩阵按任务写入skill-preparation相应目录或规则来源文件；本轮表内“值得吸收”不是已经采纳。

## 发布能力和官方资料

GitHub原仓库用于源码和版本溯源，skills.sh／SkillsMP／Jiuwen用于发现来源。LinkedIn、X及其他平台官方资料用于确认内容对象、限制、权限和接口；它们不是同名社区skill的能力保证。

上述候选多数提供文案、脚本、图片要求或素材包，**没有证明能直接替代本项目LinkedIn／X已实现的发布适配**。后续知乎可从[既有官方发布核查](发布接入与工作台调整记录.md)继续调查，但未把其中仅链接的外部发布项目误列为本批已完整归档skill。平台能力会变，准备真实接入时重新核验官方来源和账号条件；普通的本地规则比较无需重新找原件。

现有候选质量证据也有限：0.2.1验证只有两个双语样本的14次成功调用，跨0.2.0／0.2.1合计37次不等于最终版37次；自然稿审核多数零发现不能证明召回稳定。X最新真实双语和四图成功是具体样例证据，不能扩大到所有题材。详见[候选验证](../skill-preparation/linkedin-text/validation.md)、[X验证](x/validation.md)。
