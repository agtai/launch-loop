## 本轮交付与覆盖

## 去重与冲突处理

| 重复或冲突 | 本轮统一规则 |
|---|---|
| 多个skill都要求读产品背景、明确受众和目的 | 统一到base.evidence/base.writing；不新增独立研究关卡，不让用户重复填写。 |
| copy-editing七轮sweep、persona评分、迭代，与一次自动审核冲突 | 合并成一次审核的检查维度，再统一修订；不运行原多轮流程，也不虚构专家评分。 |
| copywriting要求“更自信”、删除限定词；shuorenhua要求保留语义 | 保留事实条件、否定、概率和责任主体。无法等义简化就保留，不为营销口吻增强主张。 |
| humanizer要求特定词密度、数字、经历与自我纠正 | 不把词数命中当错误，不凭空创造经历/数据；只报告正文可支持的具体问题。 |
| humanizer正文和checklist的折叠阈值不一致；字数和词数混用 | 不采纳210/265字符折叠线、固定句数和900–1300“最佳”区间；中文不套英文词数。 |
| 社区把正文外链列为算法阻断，强制个人号、暖场、首小时互动 | 不采纳为平台规定；本轮不执行发布、评论或运营排期。链接只检查目标与上下文。 |
| 作者固定核心信息含旧6×/25×、模型顺序、发布时间 | 与当前产品来源逐项核对。无法支持当前概括时不塞入新稿，保留缺口与作者确认事项；原始参考不修改。 |

补读结论：上述media-writer通用原则与现有base.evidence、base.writing、base.workflow及语言片段重复，没有新增运行时规则。本次仅补来源和比较记录，`catalog.mjs`、解析器、ruleSetVersion及已验证试稿规则hash保持不变；没有启动第二轮试稿。其平台指南、作者persona、细节编辑或执行手册未在本轮加载，也未据此宣称执行了完整media-writer工作流。

整合文本是本项目自己的短规则，未复制第三方大段正文。来源许可已记录，但许可未知的本机技能和用户资料没有被作为完整技能再分发。官方帮助网页没有可固定的commit，记录核查日期及URL，哈希留空而不编造。

## 官方边界核查

2026-09-23实读LinkedIn官方[Post and share updates](https://www.linkedin.com/help/linkedin/answer/a528176)，其普通动态上限为3000字符。解析规则要求本地同时报告代码点和UTF-16长度，平台对复杂字符的实际计数与提交结果仍需后续接入验证。社区所谓“最佳长度”、外链处罚、AI检测分值、必选发布时间不因此成为官方规则。

LinkedIn官方[Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api?view=li-lms-2026-09)中的article创建示例含source URL及卡片标题/描述，不能据此推导Pulse正文创建能力。本轮只试写feed动态，没有任何原生长文或发布API操作。

## 实际试稿验证

本轮当前Codex会话Agent已按解析后规则，以用户仓库内launch-copy的LinkedIn部分和上述固定产品commit资料，完成中文、英文各一份普通动态的初稿、一次内部审核和修订候选稿；不是硬编码演示文案，也不是工作台后端Agent接入成功。没有重新抓取用户已发布Pulse页面；本轮实际使用的是已保存在仓库的用户文章/动态正文参考。

全部正文、审核发现、规则快照、资料缓存及会话执行证据仅在 `tmp/round1-writing/`，没有写入正式内容库、正式执行日志或公开静态目录。中文修订稿本地540字符，英文1068字符（该样例代码点/UTF-16计数相同）；英文固定标题保持原文，中文译标题与两稿均待作者确认。具体稿件与发现不在永久文档复刻。

配图brief已交主Agent；主Agent本会话实际调用内置imagegen一次成功，并保存概念图到 `tmp/round1-assets/`。规则Agent实际查看图片，与两稿共同关联：有限选项→决策模型→单一选择，LLM分工另列；无性能数字、真实截图伪装或自动回退承诺。图中文字是英文，共用图不等于已完成中文本地化素材。素材与正文仍待用户确认。

该试稿验证发现并处理了术语漂移、指代含糊、LLM分工遗漏和builder边界表述；保留作者确认项。未复测产品基准，不把历史数字或单次结果当通用收益；未运行ai-rhetoric-lint，不写linted；未调用第三方检测器，不写平台审核通过。
