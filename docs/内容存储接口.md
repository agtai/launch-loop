# 内容存储接口（第一轮底层）

更新：2026-09-23。本文件描述第一阶段复用至今的本地存储、暂存、明确确认保存与版本；这些存储接口本身不调用Agent或发布。第二阶段新增执行编排、LinkedIn适配及可选publishing备份扩展，见[执行与发布接口](第二阶段执行与发布接口.md)。正式记录和tmp边界不变，示例与普通测试均为合成资料。

2026-09-24 交接澄清：由第二位负责人在自己的电脑接手运营，全部内容随项目目录保存。`tmp` 指指定数据目录下自动创建的临时文件夹（默认 `data/tmp/`），不是单个文件，也不绑定开发者用户名或固定绝对路径。无需存储迁移；完整目录交接保留未确认草稿，JSON运营备份继续只含正式版本。当前没有多人远程只读权限系统。

## 类型契约

每个正式 `ContentItem` 是一个平台 × 语言变体；同一变体内的多种格式归入 `documents`。平台／语言配置可以为空，暂存中的实际平台／语言可以是 `null`，不设置未确认的默认值。正式确认必须已有实际平台、语言及非空正文。

```ts
type ContentPlatform = 'linkedin' | 'x' | 'xiaohongshu' | 'zhihu' | 'bilibili';
type ContentLanguage = 'zh' | 'en';
type ContentFormat = 'short_post' | 'long_article' | 'thread';
type ContentKind = 'linkedin_article' | 'linkedin_post' | 'article' | 'post' | 'thread';
type ContentBlock = { id: string; type: 'paragraph' | 'heading' | 'list' | 'quote'; text: string };
type ContentDocument = { id: string; kind: ContentKind; title: string; blocks: ContentBlock[]; postingNote: string };
type ContentSource = { id: string; label: string } & (
  | { type: 'text'; text: string }
  | { type: 'url'; url: string }
  | { type: 'asset'; assetId: string }
  | { type: 'saved_version'; itemId: string; versionId: string }
);
type ContentBrief = {
  materials: ContentSource[]; purpose: string; audience: string;
  platforms: ContentPlatform[]; languages: ContentLanguage[]; formats: ContentFormat[];
  authorIdentity: string[]; styleTerms: string[]; lengthDepth: string[]; references: ContentSource[];
};
type ContentRuleMetadata = { ruleSetVersion: string; fragmentIds: string[]; hash: string };
type ContentExecution = {
  provider: string; model: string; runId: string;
  stage: 'generation' | 'review' | 'revision' | 'asset_generation';
  status: 'started' | 'succeeded' | 'failed'; startedAt: string; finishedAt: string | null;
};
type ContentDraft = {
  name: string; projectId: string | null; platform: ContentPlatform | null; language: ContentLanguage | null;
  brief: ContentBrief; documents: ContentDocument[]; sources: ContentSource[]; assetIds: string[];
  rule: ContentRuleMetadata | null; executions: ContentExecution[];
};
type ContentAsset = {
  id: string; fileName: string; mimeType: string; byteLength: number; sha256: string;
  source: { kind: 'upload' | 'generated'; url: string | null }; caption: string;
};
type ContentUploadInput = Pick<ContentAsset, 'id' | 'fileName' | 'mimeType' | 'source' | 'caption'> & { dataBase64: string };
type ContentTmpCreateInput = { content: ContentDraft; base?: ContentBase | null; uploads?: ContentUploadInput[] };
type ContentTmpUpdateInput = { revision: number; content: ContentDraft; temporary: ContentTemporary };
type ContentConfirmInput = { revision: number; confirmed: true };
type ContentBase = { itemId: string; revision: number; versionId: string };
type ContentTemporary = { initialDocuments: ContentDocument[]; reviewFindings: string; prompt: string };
type ContentTmp = {
  id: string; revision: number; createdAt: string; updatedAt: string; restoreEpoch: number;
  base: ContentBase | null; content: ContentDraft; temporary: ContentTemporary; assets: ContentAsset[];
  confirmed: { itemId: string; versionId: string; at: string } | null;
  stale: boolean; // 返回时计算，不写入 tmp 文件
};
type ContentVersion = { id: string; number: number; createdAt: string; content: ContentDraft; assets: ContentAsset[] };
type ContentItem = { id: string; revision: number; createdAt: string; updatedAt: string; currentVersionId: string; versions: ContentVersion[] };
type ContentSummary = { id: string; name: string; platform: ContentPlatform; language: ContentLanguage; revision: number; updatedAt: string; currentVersionId: string; versionNumber: number };
type ContentBackup = { schemaVersion: 1; items: Array<Omit<ContentItem, 'versions'> & { versions: Array<Omit<ContentVersion, 'assets'> & { assets: Array<ContentAsset & { dataBase64: string }> }> }> };
```

ID 限制为 ASCII 字母、数字、`_`、`-`，最多 120 字符；服务生成的作品、版本、tmp、素材 ID 为 UUID。`projectId` 只是可选关联，当前没有新增项目管理接口。执行元数据只接受上述白名单，禁止把正文、提示词、审核全文、素材正文放入日志字段。一次 tmp 中审核最多一条执行记录；再次运行应显式新建 tmp。它记录调用状态，不证明真实调用已经接通。

## HTTP 接口

所有接口沿用当前服务 Host、Origin、Sec-Fetch-Site 检查；写请求必须是 JSON。失败返回 `{error}`，非法输入 400，找不到 404，并发冲突／恢复后暂存失效 409，容量超限 413。

| 方法与路径 | 输入／输出 |
|---|---|
| `POST /api/content/tmp` | `{content, base?: ContentBase \| null, uploads?: Array<{id,fileName,mimeType,dataBase64,source,caption}>}` → 201 `{item: ContentTmp}`；首批上传支持仅用文件作必填资料 |
| `GET /api/content/tmp` | `{items: ContentTmp[]}`；单独的暂存入口，正式列表不含这些内容 |
| `GET /api/content/tmp/:id` | `{item: ContentTmp}` |
| `PUT /api/content/tmp/:id` | `{revision, content, temporary}` → `{item: ContentTmp}`；完整替换可编辑部分 |
| `POST /api/content/tmp/:id/assets` | `{revision,fileName,mimeType,dataBase64,source,caption}` → 201 `{item: ContentTmp, asset: ContentAsset}`；自动选入 `assetIds` |
| `GET /api/content/tmp/:id/assets/:assetId` | 实际二进制下载，`Content-Disposition: attachment` |
| `POST /api/content/tmp/:id/fork` | `{revision,base: ContentBase \| null}` → 201 `{item: ContentTmp}`；显式复制旧暂存与素材，取得当前恢复 epoch。指定当前正式 base 即再次修改该作品，`null` 即新作品 |
| `POST /api/content/tmp/:id/confirm` | `{revision,confirmed:true}` → `{item: ContentItem, version: ContentVersion}`；用户明确确认才写正式库 |
| `GET /api/content` | `{items: ContentSummary[]}`；只含正式作品 |
| `GET /api/content/:id` | `{item: ContentItem}`，所有已确认版本 |
| `GET /api/content/:id/versions/:versionId` | `{version: ContentVersion}` |
| `GET /api/content/:id/versions/:versionId/assets/:assetId` | 对应不可变版本的二进制下载 |
| `POST /api/content/:id/revise` | `{revision}` → 201 `{item: ContentTmp}`；将当前正式版本与二进制复制到 tmp，正式内容不变 |

LinkedIn 只能用 `linkedin_article`、`linkedin_post`；其他平台使用 `article`、`post`、`thread`。这是存储形式约束，不表示平台已提供这些对象的发布接口。空选项数组原样保留。资料、目的、读者三项必须有效，其余配置可空。来源中的 `saved_version` 必须指向已有正式版本；资产来源必须指向该 tmp 所持有、且选入 `assetIds` 的实际文件。文件上传只接受字节，不接受本机路径，不从 URL 自动下载；素材 `source.url` 是归属记录而非抓取授权。

首批 `uploads` 的 `id` 是请求内关联标识，例如 `input-file`；`brief.materials` 可直接引用 `{id:"material",label:"已有文档",type:"asset",assetId:"input-file"}`。服务校验文件后生成真实素材 UUID，替换该请求内所有素材引用并自动选入 `assetIds`。这样仅上传文档也能满足资料必填，无需先虚构一段材料才能创建 tmp。首批上传总量仍受单次 8 MiB JSON 上限约束，后续上传使用独立 assets 接口。

## 暂存与确认的边界

未经确认的 `content`、初稿 `initialDocuments`、提示词、审核全文与素材文件只在 `dataDir/tmp/content/` 下。文件写入采用 SQLite 进程间事务锁与原子重命名，修改检查 revision；锁不保存暂存正文，进程退出后由系统释放，不使用可能永久遗留的磁盘锁文件。暂存载荷不进入 SQLite、正式日志或备份。服务不清理 tmp；确认后以安全 ID 元数据记录确认收据，不能继续修改已确认 tmp，可以 fork。恢复也不清理 tmp。

确认只复制 `content` 和它选中的实际素材；`temporary` 永远不进入正式版本。正式版本与素材二进制在同一 SQLite 事务中写入。已有作品的 `base` 同时检查 item revision 和 currentVersionId；过期修改不能覆盖新版本。版本内容没有更新／删除接口。确认保存没有发布权限、发布链接或平台审核通过状态。

对已有稿件发起修改时用 `revise`；对恢复前的过期 tmp 用 `fork`，由调用者明确提供当前正式 base，或者明确选 `base:null` 保存为另一作品。不会自动把过期内容覆盖恢复后的数据。

## 迁移与恢复语义

启动时显式创建内容 schema version 1 的独立表，保留原 `records` 表所有模块／任务。协议仍是 `app: "content-workbench-local", version: 1`。新备份追加可选 `content` 扩展，包含所有正式版本及其实际素材 Base64；不含 tmp。旧程序不能读取这一扩展，需要使用本轮或更新服务恢复新备份。

恢复先验证整份备份、所有来源引用、文件长度及 SHA-256，再在一个事务内处理旧模块／任务与内容：

- **没有 content 的旧备份**：恢复旧模块／任务，保留当前全部正式内容，增加其 revision。
- **含 content 的新备份**：正式作品集合恢复成备份中的集合；当前但备份中没有的作品从活动库移除，恢复前快照完整保留它们。相同版本 ID 若已有内容不同则拒绝，不能借恢复改写不可变历史。
- 每次成功恢复均增加 restore epoch；所有旧 tmp 保留可读，但不能更新／上传／确认，需显式 fork。所有当前作品 revision 增加，恢复回来的作品也取得新的 revision，旧客户端不能继续写入。新 revision 只从本机单调计数器分配，不用备份传入的任意大数抬升计数器；若恰好与传入 token 相同，只跳过该值一次。因此合法但接近安全整数上限的备份 revision 不能耗尽本机后续写入空间。
- 验证失败不创建快照，不修改数据库；事务失败回滚全部数据库修改。恢复前快照保存当时正式内容，不包含 tmp。

单个素材最多 4 MiB；单次内容 JSON 请求最多 8 MiB；备份及恢复最多 16 MiB（按紧凑 JSON UTF-8 计，磁盘快照也使用紧凑 JSON）。正式作品最多 10000 条，每份作品最多 10000 个版本；确认与恢复使用相同上限。确认及旧模块／任务更新时检查完整备份容量，超过限制回滚写入；导出也明确拒绝超限，不能生成不可恢复的新备份。所有 revision／epoch 增量均检查安全整数范围，溢出回滚。备份包括素材字节，因此恢复不依赖旧电脑的本机路径。容量策略后续可以升级，不截断、不伪造成功。

只接受 HTTP(S) 来源 URL，拒绝凭据、控制字符、反斜杠及本机文件协议。文件路径由服务端 ID 构造，逐段检查文件系统链接与目录边界，不接受任意路径或跨 tmp 资产引用。素材下载强制附件、禁止 MIME 嗅探，不把上传的 HTML 当页面执行。
