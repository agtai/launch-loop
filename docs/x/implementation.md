- 基线发布存储仅支持 LinkedIn 单步；X 增加独立多步适配和备份扩展，仍使用同一 SQLite、确认版本与恢复事务。

## 文本与图片编排

X 使用 `共同 mother → 母稿语言的 X adaptation → 逐语言 localization → 冻结全部初稿 → 每语言包 review 一次 → revision`。每份语言包中的普通帖和完整串帖在同一次内容审核中检查，不为两种格式或每条子帖增加审稿调用。确定性逐帖格式与官方加权计数检查不算额外内容审核。

母稿规则不带目标语言、逐帖格式、字数或图片执行片段；原文语言根据实际资料中承载主线的内容决定，目标语言顺序、界面语言、目的/读者说明的填写语言均不决定母稿语言。源平台稿按 `mother.sourceLanguage` 解析完整 X 规则；同语言逐字透传，其他语言从同一平台稿本地化。修订保持该语言已有 document ID、帖子 ID、顺序和条数，超限正文保留并提示，不截断或拆帖。详细规则与来源见 [文本接入](text-generation.md)。

**混合 LinkedIn + X 请求仍有范围限制：**先执行 X 的共同母稿流程，再执行 LinkedIn 原有独立流水线。两平台未共享同一个生产母稿，不能把 X 的共同母稿能力称为已完成跨平台统一编排。LinkedIn 串帖及其他待适配选择仍被规则解析器拒绝执行。

所有 X 终稿成功写入 tmp 后，`onXReady(tmpIds, finalTexts)` 调用一次独立图片调度，`finalTexts` 为每份文本实际保存返回的 `{tmpId, revision}`。首次调度必须匹配这份冻结版本，不能回调时重新读到用户新编辑的版本后当作原终稿；等待另一语言完成期间已改动或选无图的内容包会跳过自动配图。有上传图则检查，无图则生成；每个内容对象一项任务，同一个 tmp 串行处理，后续对象仅承接本次图片任务返回的 `resultRevision`。后台只在真实图片、视觉检查、当前正文/hash/版本均吻合时附图；任务失败保留正文，正文修改、取消、恢复、显式无图等变化会阻止迟到结果附入。文本服务不等待图片完成；局部改稿及重启不会自动重生图片。图片状态、失败原因与显式重试在工作台独立显示，详见 [图片接入](images.md)。

## 数据与所有权

一份作品仍是平台 × 语言；格式多选只增加 documents。X 普通帖 `kind=post`、串帖 `kind=thread`，每帖独立 `blocks[]`，`type=x_post`，包含稳定 id、实际提交 text、可选 assetIds 和图片绑定。数组顺序即发布顺序；版本由不可变 ContentVersion 承载。普通帖恰一条、串帖 2–25 条（25 是项目首版上限）。title 强制为空，内部名称使用作品name和格式标签；不会拼入 X 正文。最终计数、预览与提交使用同一个 text，不隐式加编号、删字或拆帖。

| 所有者 | 文件边界 |
|---|---|
| 主 Agent | 共享类型、内容验证/保存、HTTP组合、前端、依赖、文档、dist、整体验收 |
| 文本 Agent | X规则、官方计数、rule-resolver、generation-service、文本专项测试 |
| 图片 Agent | X视觉规则、brief与绑定、受控图片执行器、按对象后台任务、图片专项测试 |
| 发布 Agent | X OAuth/API、发布状态机、独立发布store、HTTP、专项测试 |
