# MVP 体验审计：Easy、Hands-off、Transparent

审计日期：2026-09-24。对象为 `codex/mvp-integration` 的当前实现与 `http://127.0.0.1:4348/` 实际工作台。本文是评估和改造建议，不表示这些建议已获开发授权或已经实现。

2026-09-25：用户要求记录本次评估；结论与改造建议已纳入 [会话交接](SESSION_HANDOFF.md)，作为后续待办。本次未启动改造。

2026-09-26 补充：本文保留当时 LinkedIn 分支的问题与证据，不能将“图片未通过”等旧判断泛化为后续 X 实测。当前状态看[会话交接](SESSION_HANDOFF.md)；后续实现遵循[任务交互与恢复规范](任务交互与恢复规范.md)，独立门槛见[四项目标体验验收](四项目标体验验收.md)。[开发总清单](开发总清单.md)已将共同任务契约前移、图片／恢复／基础易用性纳入 P0 体验，并新增 UX-07；下文 P0／P1 为历史建议，不替代最新排期。本次只补文档，未实施或验收改造。

## 结论

**当前部分满足，尚不能认定三个目标全部达成。** 已有自动创作主链路和较完整的数据保护；主要差距是普通操作者理解当前结果、运行中改变方向，以及异常发生后的连续操作体验。即使网络完全正常，这些设计缺口仍然存在。

| 目标 | 判断 | 已成立的部分 | 阻止完整达标的部分 |
|---|---|---|---|
| Easy：容易开始、容易找到结果、容易知道下一步 | 部分满足 | 三项必填；平台及语言有可见预设；用户不必选择 skill；正文可直接编辑 | 可选配置默认全部展开；待适配平台可选但会阻止生成；执行历史压过当前结果；首次发布配置仍需维护者 |
| Hands-off：启动后自动推进，只在需要人的判断时打断 | 正常文本链路已实现；完整交付未达标 | 母稿、平台改写、本地化、每稿一次审核、修订自动串联；图片有后台生成和检查路径 | 异常续接只覆盖特定失败阶段；没有统一的补资料后继续入口；图片尚无真实合格交付，发布尚无真实外部验收 |
| Transparent，并能 intervene at any point | 有状态与追溯基础；“随时介入”未满足 | 阶段、失败、正文保留、审核记录可查；完成后的选区改稿可接受、拒绝、撤回；发布前核对版本与账号 | 审核以 JSON 展示；来源、规则、修订关系没有用户视图；运行中只有取消，缺少暂停、调整、按受影响阶段继续 |

Hands-off 的验收终点应是“得到可审阅成果或明确待决事项”。用户确认正式保存、核对具体账号及内容后确认发布，是现有产品要求，不应为了自动化去掉。外部发布已提交后，不能承诺随时撤销平台动作；应明确显示这一边界。

## 已满足部分的证明

### 1. 不需要操作者理解或选择 skill

当前真实页面只有产品资料／已有内容、写作目的、目标读者三项必填；LinkedIn、中英文、普通动态预设明确可见。`generate()` 同样校验这三项，而非只在文案中描述。

规则解析器把内容规则、LinkedIn 规则、本地化规则、审核修订规则与选项拼成完整规则，记录版本和 hash；按阶段提供各自需要的规则：

| 阶段 | 实际职责 | 对应规则 |
|---|---|---|
| 共同母稿 | 读取材料，确定论点、事实与术语；核心证据缺失则停下 | 内容核心规则、适用的作者规则 |
| 平台改写／润色 | 将母稿组织为源语言 LinkedIn feed 动态，并形成配图 brief | LinkedIn、素材规则 |
| 语言本地化 | 同语透传，另一语言保留相同事实和条件进行本地化 | 本地化、术语规则 |
| 一次审核 | 检查事实、目的、层次、衔接、语气、平台及语言要求 | 内容、平台、本地化、审核与素材规则 |
| 最终修订 | 根据所有已完成审核处理实际问题；无问题允许不改 | 平台、本地化、审核修订规则 |

这是已经接入执行的规则组合，不能把它描述为用户每次自行调用几个独立 skill。证据：[规则解析器](../server/text-rules-v2.mjs)第 8–40 行、[文本管线](../server/text-pipeline.mjs)第 315–459 行、[创作表单](../src/ContentWorkspace.tsx)第 175–188 行。

### 2. 正常路径能自动执行，且有明确完成边界

文本管线先完成各语言初稿并冻结，再执行每稿一次审核，收齐审核后统一修订。已成功审核在允许的续接中复用，不因恢复而重复审核。未确认内容保持在 tmp。

图片按最终正文生成、检查，只有检查通过且正文绑定有效才附入。现有真实失败图被拦截，是保护机制成立的证据；不是图片交付完成的证据。

证据：[文本管线](../server/text-pipeline.mjs)第 359–459 行；[生成服务](../server/generation-service.mjs)的 `generateAssets`、`resumeReview`；[图片边界测试](../tests/mvp-image-boundary.test.mjs)；[冻结稿续接测试](../tests/text-frozen-resume.test.mjs)。

### 3. 用户在终稿阶段有实质控制权

可以直接编辑段落、选区提出修改、比较提案、接受或拒绝，并预览撤回已接受修改。跨语言事实同步需要显式生成和接受候选，不直接覆盖另一语言。正文修改使旧图绑定失效时，有状态提示并阻止按旧绑定确认。

确认保存形成本地正式版本，不发布；发布页另行核对账号、版本、正文与图片并要求确认。已知发布结果与未知结果分开，未知结果不自动重发。

证据：[创作编辑器](../src/ContentWorkspace.tsx)第 381–388 行、[发布界面](../src/PublishingWorkspace.tsx)第 83–140 行、[改稿测试](../tests/mvp-editing.test.mjs)、[发布测试](../tests/publishing.test.mjs)。真实选区修改证据见验收报告；真实 LinkedIn 操作仍未验证。

## “随时介入”控制矩阵

| 时点 | 当前能够做什么 | 当前缺什么 | 建议达标行为 |
|---|---|---|---|
| 开始前 | 修改材料、目的、读者和选项 | 明确图片策略、精简可用选项 | 三项输入后显示本次执行摘要及图片策略 |
| 母稿／平台／本地化运行中 | 看阶段、预算；取消任务 | 在同任务暂停、读取已完成中间稿、补充指令后继续 | 随时发出介入请求；安全停止当前调用或在可控边界暂停，保留有效产物 |
| 审核／修订运行中 | 看阶段、取消；后台保留部分工件 | 可读的阶段成果与按影响范围调整 | 修改产生新修订，明确哪些审核失效，只重做受影响下游 |
| 后台配图中 | 看状态、取消 | 独立继续编辑既有正文、切换图片策略 | 允许在新修订上编辑；旧图片结果只能属于原正文，不能回写新稿 |
| 终稿待确认 | 直接编辑、选区改稿、接受／拒绝／撤回、显式语言同步、确认保存 | 清楚展示规则、来源、自动修订前后关系 | 保留现有控制，增加可读证据与变化说明 |
| 已保存、尚未发布 | 查看版本、派生新修订；发布前再次确认 | 创作到发布的连贯入口 | 直接带入已选正式版本，同时仍明确核对账号和图片 |
| 已向平台提交 | 显示提交／失败／未知；有条件查询，或人工核对 | 不能承诺撤回已发生的外部动作 | 清楚标示不可撤回边界；未知结果不重发，不提供虚假的“取消成功” |

“随时介入”应表示用户随时可以表达调整意图并得到确定反馈；不意味着任意模型内部过程都能原地暂停，也不意味着外部已发布动作一定可以撤销。

## 建议改造顺序与验收标准

下列为建议，保留三项必填、每稿一次审核、tmp、显式保存／发布、版本并发和防重要求。不扩展其他平台、视频、DOCX 或反馈。

### P0-1：以一份内容任务为主视图

将母稿、各语言、配图、改稿与恢复尝试挂在同一内容任务下。主视图先显示成果和当前状态，历史尝试默认折叠且可完整查看；保留旧记录。

当前案例应一眼显示：**中文正文已完成；英文正文已完成；配图未通过／待处理；尚未确认保存；尚未发布。** 区分“用户尚未确认”和“系统错误”。主动作随状态变成查看终稿、补充材料、继续、处理配图或确认保存。

验收：同一任务连续发生两次配图失败后，正文仍明显标为可审阅，用户能找到两个历史原因；新用户不翻日志即可回答“完成了什么、卡在哪里、下一步是什么”。

### P0-2：可读的过程与依据

增加阶段时间线：内容组织 → LinkedIn 改写 → 本地化 → 一次审核 → 修订 → 配图。每阶段展示使用了哪些材料和规则、已有成果、尚待处理事项。审核按“问题位置—依据—修改—保留原因”展示，点击可定位正文；来源提供实际引用片段。详细 JSON 留在技术详情中。

规则自动绑定不变，只增加用户可读的名称、版本及应用原因，不增加手选 skill 负担。不展示模型私有思维链或把猜测包装成原因。

验收：用户能从一条主张找到材料原文，从一条审核发现找到修订结果；没有修改时如实显示“审核未要求修改”；修改后清楚区分原审核与当前正文。

### P0-3：补齐暂停、调整、继续

建立任务输入快照和修订关系。支持“暂停并调整”：给出可控调用退出状态，用户补材料、改要求或编辑已完成稿件，系统说明哪些成果继续使用、哪些下游失效，再继续执行。取消保留为结束本次执行的独立动作。

通用续接必须校验输入、规则、正文版本及工件关系；同一冻结稿不重复成功审核，用户改变内容则形成新修订并使相关旧审核失效。不能把旧审核当作新正文的背书。配图与正文并行操作使用不同修订，取消与迟到结果保护继续保留。

验收：在母稿、平台、审核、配图阶段分别发起介入；受控任务不会继续回写被替换的修订；补充事实后只重做受影响阶段；未改动且已成功审核的冻结稿不被重复审核。介入能力的实现不要求无条件复用任何半成品。

### P1-1：把异常变成明确的待决事项

提供统一“继续此任务”，显示原始输入快照与恢复范围；无法恢复时说明原因并可带入原资料创建新尝试。缺资料时在任务内回答具体缺口。

开始前给出“自动配图／上传图片／纯文本”。失败后可以重新生成、替换图片或转为纯文本，并说明对成果的影响。有限自动修正／重试若要引入，需先明确适用错误、次数和预算；当前策略仍是不自动重试。发布结果未知保持人工核对和禁止自动重发。

验收：每类异常都有明确可执行动作，普通操作者无需进入 tmp 找日志；图片失败不迫使重写正文；打开任务不会自动触发新的付费调用或发帖。

### P1-2：精简日常页面与首次配置

高级设置默认折叠，但 LinkedIn、语言、格式及图片策略保留简洁可见摘要；暂不支持的渠道明确标为待适配并阻止选择。保留原历史入口，但降低其在日常主流程中的视觉权重。

提供配置状态清单及中文解释：哪些由维护者一次性准备、哪些由操作者登录完成、现在能否创作／发布。已有环境检查可复用；当前网络搁置期间不增加探测。保存后提供“用此版本准备发布”入口，保持独立发布确认。页面内突出完成和需要处理的状态；系统通知如需加入，由用户选择。

验收：环境已配置时，新操作者不用终端、不读实现说明、不选择 skill，即可从三项输入到审阅、改稿、确认保存和准备发布；首次配置另单独验收，不能与日常易用性混算。

## 最终如何证明达标

建议在以上行为实现后执行下列验收，而非用测试数量代替体验结果：

1. **Easy**：请未参与开发的操作者完成一份真实双语任务。记录误选、求助及找不到操作的位置；开始、找稿、改稿、保存、准备发布均不需要开发者指导。
2. **Hands-off**：一次启动后不人为点阶段按钮，自动到达可审阅文本及按所选策略处理的图片结果；切换页面再回来仍能找到同一任务。外部条件不齐时明确进入待处理状态，不能伪称完成。
3. **Transparent**：操作者能说清当前阶段、已完成成果、阻塞原因、采用的规则／材料，以及是否已经保存或发布；能从结果追到依据。
4. **Intervene**：按上面的阶段矩阵演练暂停、补资料、改方向、取消和继续，验证旧结果不会覆盖用户修改；模拟可以覆盖竞争边界，关键用户路径还需真实调用验收。
