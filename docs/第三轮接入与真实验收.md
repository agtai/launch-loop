## 查看与复现

本机保留隔离验收服务 `http://127.0.0.1:4336` 供看稿，数据在`tmp/round3-browser/data/`，并非日常`data/`。在创作任务中选择已完成的中／英文稿；暂存草稿中最后一份同名中文稿是已接受局改且继续手动编辑的稿件。均显示待确认，未正式保存。停止时运行该隔离目录的`Stop-Workbench.ps1`，不要停止无关服务。服务重启后任务和tmp保持，未自动调用模型。

需要重新打开已保留验收数据时，在仓库根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tmp\round3-browser\Start-Workbench.ps1 -Port 4336 -NoBrowser -UseSystemProxy
```

该临时副本不会随Git克隆；接手者日常使用根目录启动器及其自己的正式登录。新一轮真实生成操作为上传真实TXT／MD材料、填写目的和读者、选择LinkedIn／中英文／普通动态，再点击生成；完成后在右侧看稿、手改或选区改稿，最后由用户决定是否确认保存。配图入口未补齐前仍会明确显示未连接。重跑会消耗操作者模型额度，历史成功不能替代本次完成事件。

## 交接方式澄清

用户明确“多人”是先由用户开发和试用，再交给第二位负责人在自己的电脑运营生成和发布；所有内容保存在第二位负责人的项目目录，其他人希望通过工作台查看。沿用项目相对 `data/` 与自动创建的 `data/tmp/`，不绑定开发者机器；不迁移账号凭据、不清理已有数据。用户早先提到系统临时文件夹，主 Agent 曾考虑 OS tmp；在“所有内容位于项目目录”的后续澄清后没有实施该改动。其他人的只读访问需要独立的访问控制，当前仍监听127.0.0.1，本轮不擅自公开服务。

现有Codex CLI是优先复用已有账号的当前适配，不代表永久只支持Codex，也不是所有查看者都需安装Codex。后台配图候选尚未选定；内置图片会先使用Codex工具缓存，用户尚未明确批准缓存例外，不将架构问题或澄清视为授权。
