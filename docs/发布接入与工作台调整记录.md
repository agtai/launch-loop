- 移除独立研究和审查模块。创作内部为生成初稿、自动审核一次、修订最终稿；在右侧窗口查看和修改，用户确认后才正式保存，确认前最多暂存在 tmp。

- 当前仍为讨论和记录阶段。产品主流程已明确，但具体 skill、界面交互与发布接入尚未完成设计和验证，不能直接理解为只剩编码。

## 工作台需要同步调整

结合已确认需求，上一轮提出以下布局与发布交互建议，供后续统一设计；不把新增建议当作已经实现或全部定稿：

| 位置 | 调整方向 |
|---|---|
| 主导航 | 创作、发布、反馈（留空）；移除独立研究和审查入口，历史资料与记录保留 |
| 创作页 | 填写资料和配置、生成及自动审核；右侧查看／修改待确认内容，用户确认后正式保存 |
| 发布页 | 选择已正式保存的稿件、平台、具体内容类型和账号，右侧预览；区分账号未连接、待用户操作、已提交、已发布及失败等真实状态 |

发布能力需要按“平台＋内容类型”判断。例如 LinkedIn 动态和原生长文章不能共享一个笼统的“支持发布”结论。最终状态应以实际平台结果为依据，提交成功与已经公开发布也可能不同。

## 五个平台的官方资料核查

### LinkedIn

普通动态有官方发布 API，可发布文本及支持的媒体／链接内容；个人发布需要用户授权及 `w_member_social` 权限。依据：[Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api?view=li-lms-2026-09)、[Share on LinkedIn 授权说明](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/share-on-linkedin)。

原生长文章另行处理：Posts API 的 `article` 示例为带 `source` URL 的链接卡片，不是写入 Pulse 正文。本轮仍未找到可依赖的公开原生长文创建接口，不能将“可发动态”推导为“可发原生长文章”。具体边界沿用 [LinkedIn 发布与反馈接入核查](LinkedIn发布与反馈接入核查.md)，其中反馈规划已延期。

### X

官方 [Create Posts](https://docs.x.com/x-api/posts/create-post) 提供发帖接口，需应用接入及用户授权。官方 [费用说明](https://docs.x.com/x-api/getting-started/pricing) 当前采用按量付费、预购额度；实际费用接入前重新核查。存在明确的 API 路线，不代表用户已经配置开发者应用、额度或授权，本次未购买服务。

### 小红书

官方 [分享能力概览](https://agora.xiaohongshu.com/doc) 和 [Android 接入说明](https://agora.xiaohongshu.com/doc/android) 支持把图文／视频带入小红书 App 的发布流程；[iOS 接入说明](https://agora.xiaohongshu.com/doc/ios) 涉及应用登记、AppKey 和权限审核。

这是分享进 App 的能力，不足以证明后台可以无人值守地完整发文。官方 [FAQ](https://agora.xiaohongshu.com/doc/qa) 还说明限制分享 SDK 自动填充标题和文案；该页标示更新于 2023-12-10，核查时仍在线，实际行为须在接入前复核。部分页面在抓取时超时，以上为本轮可取得的官方资料证据，未做 SDK 实测。

本轮未证实公开、通用的创作者笔记后台发布端点；不能据此断言所有合作渠道都不存在，也不能把账号登录 API、商家 API 当作笔记发布能力。

### 知乎

知乎官方仓库 [ZhihuPublisher](https://github.com/zhihu/ZhihuPublisher) 已提供基于 OpenAPI 的发布流程，支持文章、提问、想法，可配合图片上传；该流程目前不支持视频。需要申请发布凭证，不能由已有网页登录状态推导已经取得 API 权限。

官方配套 [OpenAPI 凭证说明](https://github.com/zhihu/zhihu-mediacloud-uploader/blob/main/references/auth-info.md) 将申请页面标为内测阶段。因此有官方 API 路线，但当前用户能否申请到权限仍未验证。本轮仅阅读资料，未安装或执行该发布 skill，也未采用其默认落盘流程；后续复用须遵循本项目的 tmp 与确认保存规则。

### 哔哩哔哩（Bilibili）

官方 [开放平台入口](https://open.bilibili.com/sys) 的可检索说明包含身份认证、创建应用和稿件分发。已读取的 [视频稿件管理文档](https://open.bilibili.com/doc/4/23d78390-4119-1e5f-2bbe-b45bd5cecdb0) 明确 `ARC_BASE` 需要申请权限及用户授权；该页是管理／删除接口证据，不能代替投稿接口验证。

本轮找到 [视频稿件提交文档](https://open.bilibili.com/doc/4/f7fc57dd-55a1-5cb1-cba4-61fb2994bf0f) 和 [专栏文章提交文档](https://open.bilibili.com/doc/4/b14b77b6-8889-8c8b-2e83-17c5a4c550fb) 的官方地址，但未能读取其正文；开放平台入口直接抓取也可能为空。当前结论仅是存在官方稿件接入方向，具体内容类型、参数、准入条件和当前账号资格仍待核查，未验证发布成功。

## API 与 Browser Use 的选择

[Browser Use](https://docs.browser-use.com/open-source/quickstart) 是浏览器执行工具，其存在不等于平台授予发布权限，也不代表已经适配本项目的五个平台。

- [LinkedIn 自动化说明](https://www.linkedin.com/help/linkedin/answer/a1340567/automated-activity-on-linkedin?lang=en) 限制第三方工具自动操作其网站；不应默认以网页机器人补齐原生长文 API 的缺口。
- [X 自动化规则](https://help.x.com/en/rules-and-policies/x-automation) 明确限制非 API 的网站脚本自动化；不能把 Browser Use 视为免 API 的通用后备方案。
- 小红书、知乎、Bilibili 的浏览器发布路线尚未完成平台规则核查或账号实测；不承诺其可稳定无人值守运行。

当前建议为：优先采用官方 API；浏览器路线按平台评估；暂不能自动完成的内容提供人工发布交接，并记录真实结果。该建议尚未落实为最终技术选型，更不构成本轮连接账号或发布授权。
