# 四项目标体验验收

更新：2026-09-26。本文把 Easy、Hands-off、Transparent、Intervene 转成可执行的验收方案，承接[体验审计](MVP体验审计.md)、[开发总清单](开发总清单.md)中的 UX-01～07／CORE-01～02，以及[任务交互与恢复规范](任务交互与恢复规范.md)。**本文新增的全部体验用例均未执行；编写方案不表示行为已实现或体验已通过。**

本文不授权开发、启动或重启服务、探测能力、模型／图片调用、正式保存真实稿件、上传或发帖。后续按当轮任务范围实施和验收；LinkedIn 原任务的网络排查与真实续接仍按其授权状态处理。

## 1. 验收对象与结论边界

| 目标 | 操作者应能做到 | 不能用来替代的证据 |
|---|---|---|
| Easy：容易开始与完成日常操作 | 在已配置环境中，从三项必填进入创作，找到当前成果，改稿、确认保存并带入指定正式版本准备发布；不需要终端、开发者指导或选择 skill | 输入框存在、测试通过、开发者自己能走完 |
| Hands-off：启动后按所选策略推进 | 正常任务一次启动后自动到达可审阅成果；缺资料、要求冲突或执行失败时形成明确待决事项，只在需要判断或授权时请人处理 | 把多次人工阶段续接写成一次无人介入成功；隐藏失败或自动放弃图片以凑完成 |
| Transparent：知道发生了什么、为什么以及下一步 | 说清当前阶段、有效成果、待决原因、已用资料与规则、审核处置、保存／发布状态，并能在页面找到相应依据 | 原始 JSON 或日志可查但普通操作者无法理解；展示猜测的原因或模型私有思维链 |
| Intervene：能表达调整意图并安全继续 | 在每个可控阶段请求暂停、调整或取消；得到确定反馈；明确复用及失效范围，旧结果不覆盖新修订 | 承诺任意模型内部状态可原地暂停，或已提交的外部动作一定可以撤回 |

验收分三层，必须分别报告：

1. **功能 MVP**：依照 [MVP 验收报告](MVP验收报告.md)、[MVP 接口](MVP执行与素材接口.md)、[X 接口](x/implementation.md)及相应开发任务验证功能。完成 MVP-05 不自动代表四项目标达标；体验用例也不能替代存储、发布与恢复协议检查。
2. **四项目标体验——创作至准备发布**：以本文 UXA-01～16 为范围。可以在尚未做真实发帖时得出此范围的体验结论；结论必须带上“创作至准备发布”，并列出外部闭环未验项目。
3. **完整外部闭环**：另需指定账号的真实 OAuth、媒体上传、具体正式版本／对象发布及线上显示证据。本文的隔离发布用例不满足这层门槛。

当前能力以[会话交接](SESSION_HANDOFF.md)、[LinkedIn 真实验收](MVP验收报告.md)、[X 验证](x/validation.md)和[整合验证记录](验证记录.md)为准：LinkedIn 真实双语文本成功曾经过人工续接，合格图与双语绑定仍待验；X 已有真实双语普通帖／串帖、四图和局改证据。它们是既有证据，不能填成本表的新一轮通过记录。两平台目前各跑母稿；本文不把跨平台单母稿写成现状，也不以额外实现 CORE-02 作为所有单平台体验测试的前置条件。

## 2. 参与者、环境与测试资料

- **操作者**：未参与本功能设计和开发、未读实现说明的新操作者。观察员提供任务目标和允许使用的资料，不讲解按钮位置、技术状态或恢复步骤；必要帮助如实记录，不能在提示后仍判对应 Easy 子项通过。内容是否符合用途由操作者或内容负责人判断，开发者不能代替其确认真实稿件。
- **维护者与观察员**：维护者事先完成运行环境、账号工具及所需配置，准备隔离数据和可控故障；观察员保存操作证据、核对调用与版本关系，不在日常路径中代操作。首次安装、应用注册、回调、登录和权限准备单列配置验收，不混入“已配置后的日常易用性”。
- **支持范围**：Windows x64、项目要求的 Node.js 版本、本机工作台；记录实际分支、HEAD、构建和运行实例版本。LinkedIn 普通动态及 X 普通帖／串帖，中英文；其他平台和原生长文保持待适配提示。不得把服务可启动等同于模型或图片能力可用。
- **数据隔离**：用本次专用 `dataDir` 和无敏感信息的资料，保留原有数据库。正常路径资料须有足够事实、限定条件与术语；异常资料分别准备“缺少关键证据”和“要求相互冲突”两份。旧数据、工件损坏、过期 revision 和发布未知状态使用隔离夹具，不能破坏真实稿件或真实发布记录。
- **调用与外部动作**：真实文本／图片验收需当轮已授权的调用范围和可用正式登录。真实未确认正文、审核、图片及完整日志只留所用 `dataDir/tmp`；Git 文档只记脱敏结论、标识与相对证据位置。真实保存、上传和发帖按具体授权单独处理。缺账号或登录时记录依赖，不以替身补成真实通过。
- **执行前记录**：本次选择的平台、语言、内容对象、图片策略、资料版本、规则版本／hash、任务输入快照、任务与修订标识，以及维护者配置完成项／缺项。未实现的网页、PDF 等读取不纳入可用前提；实际未读取的材料不能出现在“已采用来源”中。

测试类型统一记为：

| 标记 | 含义与用途 |
|---|---|
| D：确定性隔离 | 用可控执行器、受控时间点、固定工件或平台替身验证状态、调用次数、并发和迟到结果；不证明模型质量、实际图片或平台成功 |
| B：操作者浏览器 | 在界面完成操作与口头说明，观察误选、求助、找不到结果和误解；须注明后台是隔离执行还是真实执行 |
| R：真实模型／图片 | 在获准范围实际调用，并检查文本、真实图像和绑定；故障若为人工注入，明确写“真实调用＋受控故障”，不能算自然正常路径 |
| P：真实平台 | 实际 OAuth、远程媒体上传、发帖及线上核对；只在第 5 节单独授权后执行，不计入隔离测试结果 |

表中 `D＋B`、`R＋B` 表示两类证据都需要。一个场景有多个阶段、平台或故障变体时逐项留证，不用其中一个成功替代其余变体。记录实际耗时、求助与调用数量，不在本方案中虚设完成时长、成功率或新的调用预算。

## 3. 固定验收用例

所有用例的起始状态均为 **未执行**。实现缺项不预填“通过”；未来实际执行时按第 4 节判定。

| UXA-14／Intervene、Hands-off | 对开始、继续、暂停／取消、接受改稿、确认保存等可重复提交动作进行重复点击、请求重放及并发；用过期 revision 再提交修改；发布确认用替身覆盖 | 同一幂等请求不增加重复执行、候选、正式版本或平台提交；不同合法操作按真实状态处理；过期 revision 明确冲突，不覆盖新稿；按钮反馈与后端事实一致，刷新不放大副作用；保存与发布各自的保护不因统一任务入口退化 | requestId／请求与返回的对象 ID、调用／版本／提交计数、revision 冲突、浏览器反馈、替身平台账本 | D＋B | 未执行 |

UXA-10 保留当前已实现续接边界；UXA-08、UXA-11 等新交互的最终状态语义以[任务交互与恢复规范](任务交互与恢复规范.md)为准。若实施设计要改变阶段入口或次数上限，须先明确更新契约、迁移与用例，再执行验收；不能由测试脚本临时放宽。所有场景默认不自动重试模型，不增加新的重试预算，不以自动转纯文字掩盖图片失败。

## 4. 通过、失败、阻塞与证据记录

每个场景、阶段或变体使用以下状态，不用“基本通过”覆盖缺项：

| 状态 | 判定 |
|---|---|
| 未执行 | 尚未进行本方案要求的操作与观察；历史类似证据只能引用，不能直接改成通过 |
| 通过 | 所需测试类型和全部适用变体有本次证据；预期行为全部成立；操作者无需开发者指路完成对应 Easy 动作，且能正确说明该场景要求的状态与下一步 |
| 失败 | 已执行但任一预期不成立，包括事实／版本错配、重复审核或调用、旧结果覆盖、误称保存／发布、必须靠开发者指路才能继续；记录复现和修复关联，不能以最终人工修好抵消 |
| 阻塞 | 明确的实现缺项、缺少授权／账号／环境、材料或证据不可得使场景无法完成；写出缺项、已验证部分及解除条件，不按通过统计 |

预期中的失败注入与“用例失败”分开：例如图片失败后正文保留、原因可读、显式处理入口正确，可以通过 UXA-05；它不能证明真实合格图交付。无法复现所需竞争条件也不能记为通过，须补确定性控制或标明阻塞。

四项目标“创作至准备发布”达标，需要 UXA-01～16 的必需子项全部通过，并由操作者完成正常路径和状态复述。存在未执行、失败或阻塞时，只能报告已完成的阶段或单项，不宣称四项全部达标。对真实内容质量的分歧单独保留，不能把状态控制通过当作内容已获用户认可；真实图片选项未通过时，也不能靠另跑纯文字变体宣布图文体验通过。

每次执行按以下模板记录，可引用同一份证据，但注明覆盖的具体子项。运行证据放本次隔离数据目录的 tmp；公开或入 Git 的记录应脱敏，不复制真实正文、审核、图片、凭据或完整调用输出。

```text
执行日期／记录人：
用例 ID／阶段或变体／目标：
状态：未执行 | 通过 | 失败 | 阻塞
实际 HEAD／规则版本／运行实例版本：
环境配置已完成项／缺项；隔离 dataDir 相对位置：
操作者是否参与开发；观察员给予的提示／代操作：
类型：D | B | R | P；是否受控故障／替身：
本次授权范围（真实保存、调用及外部动作分别列明）：
平台／语言／对象／图片策略；资料与输入快照标识：
task/job、requestId、tmp/revision、工件／正文 hash、正式版本标识：
```

## 5. 完整外部闭环的独立门槛

UXA-16 到“准备发布”即可完成其日常体验部分。若要宣布某平台创作到真实发布闭环完成，另在 [LinkedIn MVP 验收](MVP验收报告.md)或 [X 验证](x/validation.md)逐项留证：

1. 实际应用／回调、操作者 OAuth、账号身份及所需权限；缺配置和授权失效要如实显示，不能把替身账号当真实账号。
2. 使用图片时，实际合格文件、正文与对象绑定、远程上传结果，以及该平台所需的来源声明；本地出图成功不等于平台已接收。
3. 用户明确批准的**具体账号、正式版本、正文／内容对象和配图**，以及独立发布确认。X 的一个对象获准不自动授权另一语言、另一格式或其他对象。
4. 实际平台结果、帖子 ID／URL、串帖逐帖顺序及回复关系、线上正文和图像核对；未知结果保留待核对状态，禁止自动重发。已发前缀和原有防重事实在刷新、重启或恢复后仍保留。

这四项当前均不由本文新增验收证明。缺真实资源或具体发布授权时，完整外部闭环标为阻塞或未执行；不能为补齐报告自行调用真实上传／发帖，也不能用隔离用例、测试数量或界面成功提示替代线上证据。
