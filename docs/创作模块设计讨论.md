- 创作内部增加一次自动审核：初稿生成后按所选平台绑定的审核规则检查，再修订最终稿；用户不手选 skill。

- 用户仍要求先讨论清楚。本轮不修改功能代码、数据库、构建产物或原始参考资料。
- 用户最新澄清：现在只记录，之后统一执行。审核内容确定、skill 搜集、比较整合、平台绑定和试稿均为后续待办，现在不继续执行。

## 创作输入：用户已确认

这些字段放在内容创作模块，并用小字说明填写内容；不增加独立研究入口或强制的新建项目步骤。主题／主线沿用原创作要求，以下明确除此之外的输入。

### 三项必填／必选

| 字段 | 要求 | 字段下的小字说明 |
|---|---|---|
| 产品资料／已有内容 | 必填／必选；至少提供或选用一份有效资料 | 上传文档、粘贴文字或添加产品／仓库链接，也可以选择已有稿件。Agent 将根据这些材料创作。 |
| 写作目的 | 必选，可补充说明 | 这次内容希望达到什么效果？例如介绍产品、吸引试用、解释技术或回应读者问题。 |
| 目标读者 | 必填／必选 | 这份内容写给谁看？例如开发者、产品经理或普通用户；可补充他们对主题的熟悉程度。 |

### 可选配置

用户要求提供可选项，支持按需要选择一个或多个；不恢复旧候选表中“平台必填”的建议。未选时使用默认配置，具体默认值尚待确定。用户原文中的“语音”依据其中文／英文示例按“语言”记录，视频配音属于后续视频配置。

| 字段 | 字段下的小字说明 |
|---|---|
| 平台 | 准备在哪些平台使用？可多选 LinkedIn、X、小红书、知乎、哔哩哔哩（Bilibili）；每个平台分别生成适合它的内容。 |
| 内容格式 | 想要长文章、短动态还是其他形式？可组合选择，作为同一平台和语言下的创作要求。 |

### 独立出稿规则：只按平台 × 语言

用户追加确认：「只有平台和语言需要生成独立版本，其他的可以合并。」

- 每个平台和每种语言形成一份独立产物；生成数量按实际平台数 × 实际语言数计算。未选择时沿用默认配置，不能当作生成零份。
- 例如小红书 + 中文／英文，输出小红书中文稿和小红书英文稿两份；不是一篇中英混合稿。
- 例如小红书／LinkedIn + 中文／英文，输出四份；共用主线与事实，分别适配平台和语言。
- 内容格式、作者身份、风格术语、篇幅深度和参考文章等合并为各份产物的创作要求，不因这些字段多选而继续增加独立版本。
- 同一平台和语言若选长文章及配套短动态，可在该产物内组织为不同内容部分，保持各自实际形式；不将长文与动态的平台对象混为一谈。
- 这里的“独立版本”指不同平台／语言稿件；同一稿件后续编辑产生的修订历史仍单独保留。

### 从输入表单移除的项目

用户明确不要单独保留以下输入字段：

- 必须保留／不能改的内容。
- 数据、案例和依据。
- 时间与版本背景。

事实与来源由 Agent 从已提供材料中读取，必要时核验；系统仍记录稿件修订版本和批准状态，不要求用户填写。明确的修改要求、用户已编辑的段落仍按其指示处理。预算、团队分工、账号密钥及完整排期也不是本次创作输入。

### 配图和素材：可选上传，缺省由 Agent 生成

小字说明：「可以上传已有封面、截图或其他素材，Agent 会结合它们一起创作；不上传则由 Agent 根据内容生成所需配图和素材。」

- 有上传时结合用户素材创作，保留素材来源和关联；不默认丢弃上传文件后重做。
- 没有上传或未选用素材时，默认进入 Agent 素材生成流程，不默认交付纯文字并跳过配图。
- 这是待实现行为。需要真实素材生成工具和实际产物；未连接或生成失败时显示真实状态，不把提示词当成已生成图片，也不把生成图标成真实产品截图。

## 希望读者做什么：解释与建议，尚待确认

这项配置决定行动引导（CTA），主要影响正文结尾、链接及措辞，不需要因此切换整套 skill。写作目的描述作者想达到的效果；行动引导描述读者下一步可以做什么。

建议作为可选项，默认「由 Agent 根据目的建议」，允许「不添加行动引导」。候选动作包括查看项目／资料、尝试使用、回答问题、分享经验、关注后续等。目标链接从真实资料取得，不能编造。

根据平台、内容格式和语言调整适用选项及表达；同一动作在各语言／平台稿件中分别写法，不再增加独立版本。平台规则由对应 skill 处理，语言控制表达，格式影响位置和篇幅。它是现有写作规则的输入，而非用户需要额外选择的 skill。

小字说明建议：「希望读者看完后做什么？例如查看项目、试用或留言；可由 Agent 建议，也可以不添加。」用户本轮是在询问该项作用，没有最终决定是否加入表单。

## Skill 搜集、整合与执行：用户已确认

用户要求先从不同来源找到相关 skill，逐份审阅并统一分析、总结，准备与用户选项对应的最合适规则。用户不选择 skill，执行时也不让 Agent 临时从几十个 skill 中猜选。

准备工作按以下顺序进行：

1. **搜集**：从已有技能、用户项目参考、公开仓库及作者发布的技能中寻找与文本创作有关的 skill；无关领域不纳入。
2. **实读与比较**：读取 SKILL.md 和必要的附属规则，核对来源、适用范围与依据，比较优缺点，识别重复、过时和冲突内容。
3. **提取与整合**：形成一套基础创作规则，以及平台、语言、格式、作者身份、风格术语、篇幅深度、参考稿和素材处理等可组合规则；明确取舍，保留来源与版本记录。
4. **建立固定映射**：每个用户选项对应事先整理的规则片段；选择 A 就加入 A 的规则，生成前处理冲突，不把多个完整 skill 无差别堆给 Agent。
5. **试稿验证**：用用户已有文章和选项组合试稿，检查主线、事实、平台适配和改稿体验，再调整规则。没有实际试稿前不宣称已验证或最佳。

实际执行时，为每份平台／语言稿件拼装**唯一的一套完整执行 skill／规则**：基础规则 + 对应平台与语言规则 + 其他已选配置 + 本次资料和创作要求。固定的是经过维护的规则与选项映射，不是每篇文章的主题和内容。每次记录拼装所用版本及片段，便于复现和改进。

独立稿件仍仅按平台 × 语言生成，其他选项合并到该份规则中。第一轮只整理并验证文本创作相关规则，视频在下一阶段补充；保留原始参考 skill，派生规则另存。

**当前状态**：已读过少数创作 skill，并按用户最新要求完成一轮公开平台审核候选检索与原文核查，尚未完成全面搜集、系统筛选、整合、选项映射或实际试稿验证。当前继续讨论和记录，不恢复功能开发。

规则内容可沿用以下分工，具体条目需经过上述筛选和试稿确定：

- 作者／产品规则保留主线、事实、术语及不可改的表达。
- 写作与审稿规则控制可读性、叙述一致性、局部改动范围。
- 平台规则调整开头、段落组织、篇幅、链接及素材位置；LinkedIn 长文章与动态使用不同规则。
- 生成多个平台版本时共享事实和主线，各稿分别生成、修改、审查；不能让缩短后的稿件丢掉关键事实条件。
- 来源材料或主线更新后提示受影响稿件待同步，保留用户改过的版本，不自动覆盖。
- 平台限制通过当前官方资料核查，不能把旧 skill 中的数值、固定排期或算法经验永久写死。选用写作 skill 不等于授权发帖、发信或其他外部操作。
- 记录实际执行所用规则版本、输入资料版本及输出；维护者可更新默认规则，普通作者无需理解内部组合。

示例映射：LinkedIn 长文章展开机制和论据；LinkedIn 动态提取重点并引向文章；X 串帖逐条推进同一主线。这是拟采用的创作分工，并非平台对所有内容强制要求的文风。

## 生成后的审核：用户已确认

执行顺序：**用户提交资料和选项 → 生成初稿 → 自动审核一次 → 按审核结果修订 → 展示待确认最终稿 → 用户确认后正式保存**。确认前的生成内容最多暂存在 tmp。

- 审核是创作模块内部的一步；移除独立审查模块和入口，不要求用户额外提交审核或选择 skill。
- 每份平台 × 语言稿件独立审核，平台选择固定绑定预先整理的审核规则。语言、内容格式等限制用于选取适用片段，不增加稿件数量。
- 一次审核可以检查多个维度，再统一修订；不默认追加多轮 Agent 审稿循环。后续用户主动改稿与再次审核的具体交互待讨论。
- 审核完成后输出修订稿及必要的问题说明。没有解决的事实缺口不能由 Agent 编造补齐，也不能因执行了一次审核就写成平台审核通过。
- 用户随后可查看、修改、确认最终稿；自动出稿与作者批准、对外发布是不同状态。
- **尚待确定**：审核具体检查项、各平台／语言／格式对应的 skill 及组合规则。先搜索候选、实读并比较，再试稿确定；用户不需要在候选列表中手选。

此前提前发生的只读候选检索见 [平台审核 skill 初筛](平台审核skill初筛.md)，未安装、运行、绑定或验证任何候选，不代表用户认可选型。用户已澄清只记录、之后统一执行，现已停止检索。

## 在工作台看稿与改稿：建议方案

**已确认的窗口要求**：工作台补充右侧内容查看窗口，用于查看生成的内容。本次仅记录，后续统一实现。以下具体编辑与操作方案仍待细化。

**已确认的保存要求**：生成内容须由用户确认后才正式保存；未确认内容最多停留在 tmp，不自动进入正式内容库或待发布清单。该规则包含生成后的自动审核与修订结果及生成素材；已保存内容的新生成修订也先暂存，确认后才保存新版本，原正式版本保留。确认保存不等于确认发布。tmp 的保留时间和清理方式仍待确定。

1. 完成生成、自动审核和修订后，在右侧内容查看窗口显示可阅读最终稿，切换语言、平台稿件；无需先导出 Word 才能看稿。
2. 支持直接编辑标题和正文；也可选中段落，输入“缩短”“更通俗”“补上限制”等修改意见。
3. Agent 在选中范围提出修改，展示改前／改后，由用户接受、拒绝或继续提意见。全文重写需要明确选择。
4. 未选中的部分保持原样。执行期间作者又改动原段落时，先提示比对，不能覆盖较新的修改。
5. 未确认稿件及修改最多自动暂存到 tmp；用户确认后才正式保存，重要的已确认修订形成版本节点。正式历史可读并可作为新稿起点，不自动用未确认稿件覆盖已有正式版本。
6. 审查和批准关联具体语言、平台稿件及版本。批准后的修改形成待审新版本，原批准记录保留；中英文不强制同时定稿。
7. 工作版包含来源与意见，发布版只保留适合交付的正文／素材及必要发布提示；二者来自同一份已选版本。复制正文不带内部意见。

按作品分别批准是建议，待用户确认。暂停前的“四篇固定内容共同批准”草稿不能视为需求，后续应避免用英文动态是否完成阻塞中文文章。

## 文本先行、视频随后、其他类型预留

| 后续候选：音频 | 旁白、播客等 | 脚本、声音、时间轴、音频文件和逐字稿 |

底层区分内容媒介、作品形式、发布平台和交付格式。例如“文本／长文章／LinkedIn／DOCX”与后续的“视频／产品演示／Bilibili／MP4”；用户不必分别填写四套表单。

所有媒介共用主题、主线、来源、版本、审查与批准概念；正文编辑、预览和导出按媒介分别实现。文章可派生视频，并关联采用的原稿与素材版本。现在只预留这些关联和扩展边界，不假装其他媒介已经可以制作。

视频的“脚本完成”与“成片完成”分开：成片完成须有可播放、可检查画面声音字幕的实际文件。下一阶段需要先确定从已有录屏剪辑出发，还是从脚本制作画面和声音；本文不预设供应商、付费账号或自动发布能力。
