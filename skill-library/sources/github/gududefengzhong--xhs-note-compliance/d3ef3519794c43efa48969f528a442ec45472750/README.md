# 小红书笔记合规体检器

> 🚀 **一键体检小红书笔记风险** | 词库 + 语义双层检查 | 自动生成安全改写版本

## 功能概览

这是一个**开源的 Agent Skill**，安装到你的 AI Agent 后，帮助小红书内容创作者、MCN、代运营等**在发布前自检笔记**，规避：

- 🔴 **违禁表述**：广告法红线、医疗功效宣称、站外导流
- 🟡 **易限流风险**：绝对化用语、特证功效词、诱导互动
- ✅ **隐性承诺**：语义层的效果暗示、未报备商单信号

## 快速开始

这是一个 **Agent Skill**：安装到 Claude Code、Codex、OpenClaw 等支持 Agent Skills 的平台使用——完整的「词库扫描 → 误报过滤 → 语义复核 → 智能改写」流程由 Agent 按 [SKILL.md](SKILL.md) 编排。

### 安装

```bash
# Codex 全局安装
git clone https://github.com/gududefengzhong/xhs-note-compliance.git ~/.agents/skills/xhs-note-compliance

# Claude Code 全局安装
git clone https://github.com/gududefengzhong/xhs-note-compliance.git ~/.claude/skills/xhs-note-compliance

# 可选：第三方 skills CLI
npx skills add gududefengzhong/xhs-note-compliance
```

或者直接把安装交给 Agent——对它说：

> 帮我安装这个 skill：`https://github.com/gududefengzhong/xhs-note-compliance`

（只想在某个项目里用，就克隆到该项目的 `.claude/skills/` / `.agents/skills/` 目录；其他平台把本目录放入对应的 skills 目录即可）

**小红书 RedSkill**：在挂载了本 Skill 的笔记下方复制安装口令，粘贴到你的 Agent。

> 本仓库根目录即 skill 目录（`SKILL.md` 位于根部），任一方式装完即用，无需调整结构。

装好后直接对 Agent 说话即可触发：

- 「帮我查查这篇笔记有没有违禁词」→ 体检模式：必改 Top 3 + 建议优化
- 「帮我把这篇笔记改到能发」→ 改写模式：安全改写版 + 改动对照
- 支持直接粘贴文案、给文件路径、发配图（图上的文字一并检查）

**Agent 输出示例**：

> **总评级：🔴 高风险**（3 处必改）
> 1. 「加我vx」→「想了解的站内私信我」（站外导流，平台重点治理风险）
> 2. 「三天见效」→「用了几次感觉状态不错（个人体验）」（时限承诺）
> 3. 「全网最低价」→「这个价格挺划算」（广告法绝对化用语）
>
> ✏️ **安全改写版（已通过词库复检 ✅）**：家人们！这款面膜这个价格真的挺划算，我用了几次感觉状态不错（个人体验），想了解的站内私信我～

### 环境要求

Agent 运行环境需要 Python 3.8+（Skill 内部的词库扫描脚本使用，仅标准库、无第三方依赖）。Claude Code 等主流 Agent 环境默认满足。

## 核心特性

### ✨ 双层检查

| 层级 | 负责内容 | 输出 |
|---|---|---|
| **词库 + 正则** | 写出来的违禁词、常见变体、商业信号 | JSON `hits` / 候选命中列表 |
| **语义复核** | 藏在意思里的风险：隐性承诺、创意变体导流、过度营销语气 | 最多 4 条语义提示 |

### 🔍 自动识别

- **全角/半角**归一化
- **零宽字符**还原
- **拼音变体**匹配（vx/wx/薇信等）
- **商业信号**检测（价格、购买引导、返利暗示）
- **文风指标**分析（感叹号、emoji 密度）

### ✏️ 智能改写

改写不是机械替换，而是：
- 保留原文语气和人设
- 主动加真实限定（「个人体验」「因人而异」）
- 补充真实缺点，去广告味
- **改写版会再次跑词库复检**（最多 3 轮），结果分两档：词库完全未命中才标「已通过词库复检」；仅清除高风险项时标「高风险项已清除，仍需确认中低风险」。语义风险和平台最终审核结果无法保证

## 词库规模

- **高风险词**：127 词（绝对化、医疗、站外导流、金融承诺、时限承诺、平台红线）
- **中风险词**：22 词（特证功效、营销诱导）
- **低风险词**：16 词（接商单、代购、返利等提示词）
- **正则模式**：6 类（微信变体、手机号、QQ、URL、绝对化组合、时限承诺）
- **商业信号**：3 类（价格、购买引导、返利/佣金暗示）

词库走「小而准」路线：基于公开规则（《广告法》、平台社区公约）、常见审核风险和社区反馈持续扩充（见下方反馈机制），不堆没有依据的凑数词。

## 文件说明

- **SKILL.md**：Agent Skills 格式，Claude Code、OpenClaw 等支持 Skill 的 Agent 平台通用，包含完整工作流程和使用指南
- **check_note.py**：Skill 的内部词库扫描组件，由 Agent 在工作流第 2 步调用，输出 JSON（结构见 SKILL.md）供后续复核和改写使用
- **banned_words.json**：所有词库和规则的单一来源（Single Source of Truth）
- **semantic-checks.md**：语义判定模板，Agent 按此判定词库覆盖不到的语义层风险

## 常见问题

### Q: 可以不装 Agent、只跑脚本吗？

**A**: 不建议。`check_note.py` 是 Skill 的内部组件，只覆盖词库扫描一层——误报过滤、语义复核（隐性承诺、导流变体、商单判定）和智能改写都由 Agent 完成，单跑脚本得到的只是候选命中，不是完整结论。贡献者调试词库时在本地运行它即可（见 [CONTRIBUTING.md](CONTRIBUTING.md)）。

### Q: 词库会不会有误报？

**A**: 是的，词库输出的是「候选命中」。比如「最好」作副词时（「这是最好的朋友」）不应该被拦截。所以流程里有「第 3 步：过滤误报」，Agent 或人工需要结合上下文复核。

### Q: 检查出有问题就一定会被限流吗？

**A**: 不一定。高风险（🔴）触犯《广告法》或平台红线，被拦截或限流的风险较高。但最终以小红书官方审核为准。这个工具是「发布前的风险自查」，不是绝对判决，也不能保证通过审核。

### Q: 支持非中文内容吗？

**A**: 目前词库只覆盖中文高风险词和法律风险（如《广告法》）。英文或其他语言可以用，但检查效果有限。

### Q: 为什么检查出来的改法有时很生硬？

**A**: 词库里的 `suggestion` 是「最安全」的改法示例，可能不符合你的语气。可以参考「常见违规对照」表调整，或者提交反馈（见下）帮助改进。

## 📢 反馈与贡献

### 我们很想听你的意见

如果你在用这个项目时发现了：

- 🔴 **词库遗漏**：某个高风险词应该被检查但没被抓到
- 🟡 **明显误报**：检查出的风险判断错了，规则需要改进
- ✏️ **改法建议**：改写建议不够自然，可以优化措辞
- 🆕 **新的风险模式**：发现了我们没覆盖的问题类型

欢迎以以下方式反馈：

1. **GitHub Issues**：详细描述问题 + 真实案例
2. **Pull Request**：直接贡献改进（词库扩展、规则优化等）
3. **讨论**：在 GitHub Discussions 中分享你的发现

### 反馈格式

为了让反馈快速被处理，请按这个模板提交：

```markdown
【反馈类型】词库遗漏 / 误报 / 改法 / 新规则 / 其他

【问题描述】
简要说明你发现的问题（1-2 句）

【真实案例】
提供具体的笔记文案示例

【为什么有问题】
解释为什么这条应该/不应该被检查或改进理由

【建议方案】（可选）
如果你有改进建议，可以提出来

【相关证据】
官方文件链接、被限流截图、论坛讨论等（可选但加分）
```

**反馈示例**：

```markdown
【反馈类型】词库遗漏

【问题描述】
「弹幕」这个词在带货笔记中常见，但没有被检查出来

【真实案例】
「现在弹幕功能也有返利，有朋友已经在赚」

【为什么有问题】
「弹幕」结合「返利」和「赚钱」话术，是未报备分销商单的典型信号

【建议方案】
在 `signals` 里新增 `弹幕` 相关的返利暗示正则

【相关证据】
小红书社区管理规范：禁止未报备的返利分销
```

### 反馈审核流程

- 🔵 **月审**：每月初统一审核用户反馈和 PR
- ✅ **采纳标准**：
  - 词库遗漏：≥2 用户反馈 + 有证据
  - 明显误报：能复现 + 与现有规则矛盾
  - 改法建议：更简洁/自然且不改变安全性
  - 新规则：≥3 真实案例 + 有共性
- 📋 **更新日志**：已采纳的反馈会记入 CHANGELOG.md，注明提交者
