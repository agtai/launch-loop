# 小红书笔记合规体检

> 红线词扫描 + 辅助安全改写 —— 发布前合规自查与风险提示，改写版会再次跑词库复检

## 快速开始

**输入**（文案直接丢过来就行）：

> 家人们！这款面膜绝对是全网最低价，三天见效，想要的加我vx：mm888

**输出**：

> **总评级：🔴 高风险**（3 处必改）
> 1. 「加我vx」→「想了解的站内私信我」（站外导流，平台重点治理风险）
> 2. 「三天见效」→「用了几次感觉状态不错（个人体验）」（时限承诺）
> 3. 「全网最低价」→「这个价格挺划算」（广告法绝对化用语）
>
> ✏️ **安全改写版（已通过词库复检 ✅）**：家人们！这款面膜这个价格真的挺划算，我用了几次感觉状态不错（个人体验），想了解的站内私信我～

## 适合谁、什么时候用

- **适合谁**：商单/带货博主、护肤美妆等强监管品类创作者、代运营与 MCN 审核岗
- **什么时候用**：发布前自检 / 商单文案交付前复核 / 笔记被限流后的旧文排查
- **怎么用**：直接粘贴文案、给文件路径，或把封面图/配图发过来（图中文字一并检查）

## 风险等级说明

| 等级 | 含义 | 要处理吗 | 典型 |
|:---:|---|:---:|---|
| 🔴 高 | **违禁**：触犯广告法或平台红线，有被拦截、限流甚至账号处罚的风险 | 必改 | 绝对化用语、医疗功效、站外导流、收益承诺 |
| 🟡 中 | **易限流**：不违法但降低分发权重，或需资质才能宣称 | 强烈建议改 | 特证功效词、诱导互动、站外链接 |
| 🟢 低 | **提示**：单独出现没事，密度高可能拉低笔记质量分 | 酌情 | 接商单、代购、返利等营销词 |
| ✅ 通过 | 词库未命中 | 仍做语义复核 | — |

## 三条铁律（报告结论的依据）

1. **《广告法》第九条**：「最X」「第一」「国家级」等绝对化用语不得出现，商单审核风险高
2. **站外导流属高风险行为**：微信号及一切变体（vx、薇信、emoji 替代）是平台重点治理对象，可能严重影响审核和账号安全
3. **特证功效需资质**：美白、祛斑、防晒、防脱等宣称需特殊化妆品注册证，否则易被限流

## 常见违规对照（改写时的风格参照）

| 分类 | ❌ 修改前 | ✅ 修改后 |
|---|---|---|
| 绝对化用语 | 全网第一的美白精华 | 我用过里最合心意的提亮精华（个人向） |
| 医疗功效 | 消炎祛痘，三天见效 | 温和舒缓，用了一阵子感觉痘印淡了些（个人体验） |
| 特证功效 | 美白淡斑一步到位 | 提亮肤感，肤色看起来更均匀了 |
| 站外导流 | 想要链接的加我vx：xxx | 想了解的姐妹站内私信我 |
| 金融承诺 | 跟着买稳赚不赔 | 分享我的思路，投资有风险，仅供参考 |
| 诱导互动 | 评论区扣1私发你 | 感兴趣的评论区聊聊 |
| 隐性承诺 | 同事都问我是不是做了医美 | 我自己感觉状态好了些，因人而异 |

## 两种使用场景

- **场景 A（自检）**：用户明确说「帮我查查 / 检查一下 / 有没有问题」→ 输出【必改 Top 3】+【建议优化】核心改进清单（第 5 步），结尾问一句「要不要我直接改成能发的版本？」
- **场景 B（改写，默认）**：用户说「帮我改 / 改到能发」，**或只粘贴了文案没说要干嘛** → 按改写处理：先给【安全改写版】+ 改动对照（第 6 步），完整清单放后面。来用这个技能的人，最终要的都是能发出去的文案

## 工作流程

### 第 1 步：拿到笔记全文（含图片文字）

- 用户给文件路径 → 直接读取；粘贴文本 → **优先通过 stdin 直接传给扫描脚本，不落盘**。确需落盘时（如多轮改写对比）写入系统临时目录，复检结束后删除——用户贴的可能是未发布的商单稿，不要在用户项目里留下草稿文件
- **图片处理**：用户提供图片时直接多模态读图（无需外部 OCR 工具）。具体流程：用户给出图片路径或上传 → 用读图工具**逐张**读取（Claude Code 中即 Read 工具，其他 Agent 用各自的图片读取能力）→ 提取图中全部可见文字 → 以「[图X] 」为前缀拼进待检文本 → 一起送进 check_note.py。封面图（图1）审核权重最高，单独标注；重点看角落、水印、贴纸里藏的联系方式
- 用户没提图片时，**主动问一句**：「笔记有配图吗？图上的字也会被审核，发我可以一起查」
- 如果当前环境读不了图，友好地说明一下，请用户把图里的文字打出来发过来，一起检查

### 第 2 步：跑词库扫描

先定位本 Skill 所在目录（即本 SKILL.md 所在目录，下称 `<skill_dir>`）——**Agent 被触发时 cwd 通常是用户的项目目录，不要假设脚本在当前目录下**：

```bash
# 用户给了文件路径
python3 <skill_dir>/scripts/check_note.py <笔记文件> --json

# 用户粘贴的文本：走 stdin，不落盘
python3 <skill_dir>/scripts/check_note.py - --json   # 文本从 stdin 传入
```

脚本输出：

- 候选命中（`hits`）：违禁词和高风险表述
- 必改清单（`top_fixes`）：自动挑出的 Top 3 必改项
- 商业信号（`signals`）：价格/购买引导/返佣暗示等——**不计违禁分，不是违规项**，只用于判断是否需要商单报备
- 文风指标（`metrics`）：感叹号/emoji 密度，供营销语气判断参考

已内置全角/半角归一、零宽字符还原、拼音变体匹配。

JSON 结构：`{verdict, verdict_text, counts, top_fixes, hits, signals, metrics}`；`hits` 每条含 `term / matched / category / risk / priority / why / suggestion / line / snippet`。`top_fixes` 已按「风险等级 → 类别优先级（导流/医疗/红线 > 绝对化）」排序，同类问题只占一个名额。

### 第 3 步：过滤误报

脚本输出是**候选**，逐条结合上下文剔除明显误报（详见 `references/rules.md` 第四节）：
「最好」作副词、「第一名」叙述个人经历、「治疗」出现在就医经历分享等。拿不准的保留并标注「需人工确认」。

### 第 4 步：语义复核

按 `references/semantic-checks.md` 的判定模板逐类检查词库抓不到的风险，**最多报 4 条**：

1. **隐性效果承诺**——归因、他人反应、前后对比暗示效果
2. **疑似未报备商单**——结合 `signals` 判定，提醒走蒲公英报备而非改词
3. **站外导流变体**——emoji 替代、拆字、谐音、图片藏号
4. **过度营销语气**——结合 `metrics` 判定，改法核心是补真实细节和缺点

### 第 5 步：输出「核心改进清单」

按以下结构输出（完整示例见 `examples/sample-report.md`）：

1. **总评级 + 一句话结论**（风险等级见上表）
2. **【必改 Top 3】**：最危险的 3 处，每条给「一句话改法」，可直接替换
3. **【建议优化】**：最多 2 条可选项
4. **【语义层提示】**：第 4 步的发现（如有）
5. 完整命中明细放最后（用户要细节再展开）
6. 固定声明：本报告为发布前辅助自查，不构成法律意见，最终以平台审核为准

原则：**每条都给能直接替换的改法，不能只说「有问题」**；明确区分「违禁（必改）」和「易限流（建议改）」。

### 第 6 步：智能改写与复检循环

改写不是机械换词，按以下规则整篇重写：

1. 逐条落实必改项和建议项，优先采用词库 `suggestion` 和「常见违规对照」的写法
2. **保留原文语气、人设、emoji 习惯**——改完还得是用户自己的风格
3. 主动加一处真实限定（「个人体验 / 因人而异」）和一个小缺点，去广告味
4. **把改写稿再跑一遍 check_note.py 复检**（同样经 stdin 传入，最多 3 轮），结果标注严格分两档：
   - 词库**完全未命中**（verdict 为 pass）→ 标注「已通过词库复检 ✅」
   - 仅清除了高风险项、中低风险仍在 → 标注「高风险项已清除，仍需确认中低风险项 ⚠️」并列出剩余项，不得标「通过」
   - 注意措辞：词库复检通过 ≠ 平台审核保证通过，语义风险和最终审核结果无法承诺
5. 末尾附「改动对照」：改了哪几处、各自为什么

超过 500 字的长文，改写前先确认用户需要整篇改写还是只改命中段落。

- 🔴 **词库遗漏**：某个高风险词被限流但词库没抓到

- ✏️ **改法建议**：建议的改写能更简洁/自然
