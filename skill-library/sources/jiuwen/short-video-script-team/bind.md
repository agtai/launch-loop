# 执行护栏

## 资源限制

| 条目 | 限制 | 原因 |
|---|---|---|
| `max_parallel_teammates` | 1 | 3 阶段顺序流水线 |
| `total_wall_clock_budget` | 8 分钟 | 3 个阶段各约 2 分钟 + 简报 + 组装 |
| `total_token_budget` | 80k tokens | 脚本较短；各阶段聚焦 |
| `per_stage_token_budget` | 20k tokens | 每个阶段范围严格有限 |

## 行为约束

- **Leader 仅作编排者**：Leader 收集简报、选定钩子、组装包。Leader 不撰写钩子、内容或 CTA。
- **钩子选定门控强制执行**：在钩子选定之前，content-structurer 不得开始。Leader 选出最强的钩子，或将全部 3 个呈现给用户选择。
- **阶段顺序强制执行**：钩子 → 内容 → CTA。任何阶段均不可跳过。
- **时长纪律**：每个阶段必须尊重目标时长的字数限制。60 秒脚本 ≠ 加了填充词的 15 秒脚本。

## 失败处理

### (a) 队友失败

| 失败模式 | 应对 |
|---|---|
| 阶段超时 | 重试一次。第 2 次超时时，询问用户是否希望继续使用部分输出，或改用简化的单 Agent 脚本。 |
| 钩子选项 < 3 个 | 重新派发 hook-creator 并加入"提供恰好 3 个钩子"指令。最多重试 1 次。 |
| CTA 与视频目标不匹配 | 重新派发 cta-optimizer 并加入明确的目标说明。最多重试 1 次。 |

### (b) 输入超量降级

| 触发条件 | 降级模式 |
|---|---|
| 目标时长 > 90 秒 | 警告用户这已接近长视频；建议使用 podcast-episode-team 制作结构化的较长内容 |
| 未说明明确的视频目标 | 默认为"认知"目标；在报告中明确标注此假设 |
| 核心信息相互冲突 | 请用户选择一条主信息；短视频只能有一个 CTA |

### 升级规则

- 如果任何阶段连续失败两次，暂停流水线；输出带 `PIPELINE HALTED at Stage N` 标题的部分输出。
- 如果钩子选定受阻（用户无响应），等待 1 轮对话后超时，默认使用具有最高互动潜力技巧的钩子（大胆主张或问题式）。
