## 原件与许可

原件按来源字节保存，Git属性禁用sources内换行转换；分析意见写在清单或派生规则，不直接改原文。可取得的许可证与包一起保存；只有README／skill-card声明的许可，应与实际LICENSE文件区分；没有可靠声明则记未知。用户随后授权将这份分析资料库随本仓库commit／push；这不改变第三方许可，未知或仅有声明的状态仍保留，不据此宣称取得额外使用或再分发权。manifest的未commit／push措辞记录资料采集当时状态。

GitHub选定目录保留正文、相关参考／脚本／评估与适用许可证。Hub保留其实际发布包；两个video-studio的包本身仅SKILL.md，远程Cue服务没有随包提供。Hub仅略去Nano的一张展示封面；infographic三张核心风格参考已完整保留，其品牌图像不属于代码MIT许可。x-mentor略去推广GIF／二维码及系统文件，逐项见manifest；不宣称省略图片可离线查看。Nano约38MB的3份大型JSON提示库已保留，可在本地按主题检索，避免一次读入全部上下文。

上游相对链接若有错位，原件不修写；manifest保留已发现的链接问题和实际文件位置。第三方运行依赖、账号、供应商API、外部页面及兄弟技能未自动接入，完整度只针对归档的包／选定目录。

## 使用与更新

1. 从候选清单选择要补的缺口，打开对应本地SKILL及必要参考；不要无差别加载所有文件。
2. 与现有生产规则逐条比较，记录采用／改写／舍弃及理由、平台和执行阶段；不要执行来源脚本。
3. 需要实际接入时修改本项目规则及版本，按开发清单做边界和质量验证；归档本身不算采用。
4. 更新上游时另存明确版本和差异，更新manifest及索引；不偷偷覆盖本次快照。

离线完整性检查（在仓库根目录）：

```powershell
node skill-library/verify.mjs
```

检查包括全部记录路径、原件字节数、SHA-256、已记录Git blob SHA-1、包级校验记录一致性及未列入清单的文件。它不重新联网下载原包，不验证许可法律效力，不执行任何上游脚本，不证明skill输出质量。
