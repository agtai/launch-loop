# 本地化执行规则

状态：生产文本规则。规则版本：`text-v2.0.0`。阶段：`localize`。适用：LinkedIn 普通 feed 动态的 `zh`、`en`；界面语言不参与选择。

本文件是完整组合规则中的本地化片段；必须同时取得母稿与平台稿、来源快照、`claimLedger`、`termLedger`、作者约束和当前输入要求。不得仅凭标题或一个语言标签从头另写一篇。来源和取舍见[本地化来源](../localization-sources.md)。

## 输入、路由与输出

1. 读取母稿 `sourceLanguage` 及 `reason`。由原始材料、作者已有表达与作者明确偏好判断母稿语言；不能用 UI 语言或固定中文默认替代。多语材料以承载完整主线的作者原文为依据，记录其他材料的用途。无法辨明时记录冲突，由上游澄清关键歧义；不得补造作者偏好。
2. 读取同一份平台稿及其 `motherId`、`spine`、`claimIds`。目标语言同平台稿语言时设 `translationStatus: skipped_same_language`，正文原样传递；不要借“本地化”重写同语稿。仍进入该平台 × 语言稿唯一的一次 `audit`。
3. 目标语言不同则设 `translationStatus: localized`。以平台稿为表达输入，以母稿和原始来源为语义约束；只转换语言和必要的语序，不重新选择卖点、换作者立场或新增个人故事。
4. 输出 `variantId / platform / language / motherId / platformDraftId / ruleVersion / ruleHash / translationStatus / documents / claimAlignment / termUses / localizationNotes / unresolved`。`claimAlignment` 记录每个段落承载的 `claimIds`；无需逐句对应，不得让主张凭空出现或消失。`localizationNotes` 仅记必要改动及原因，不混入公开正文。
5. 所有真实材料派生的正文、术语上下文、提示、比对和不确定项只存本次运行的隔离 `tmp/`。本轮不生成图片、不写正式内容库。

## 语义保护顺序

处理每个含主张的句子时，先从 `claimLedger` 找到以下约束，再选择自然表达。缺字段不是让用户补一张表：由已有资料内部识别；确实未知则保留未知。

| 保护对象 | 必须保留 | 禁止替换 |
|---|---|---|
| 条件与范围 | 触发条件、适用人群、版本、环境、样本范围、例外 | “在这次离线测试中”变成“所有场景下” |
| 否定及其作用域 | 否定哪个动作、原因、结果；双重否定的原义 | “不是由于权限不足”变成“权限足够” |
| 概率与情态 | 可能、有望、可以、计划、必须的原有强度 | `may` 变成 `will`；“可以交付”变成“将交付” |
| 时间与完成状态 | 已做、未做、正在做、计划做、仅文档描述的区别 | “准备进行测试”变成“已经验证” |
| 责任主体与归属 | 谁开发、观察、主张、批准、执行；有无明确主体 | 被动句无主体时为流畅而补“我们”；引用观点改成作者背书 |
| 数字与比较 | 数值、单位、基准、方向、分母及比较对象 | 速度当准确率；成本当性能；单次结果当保证 |
| 因果和作者判断 | 相关/因果、结果/作者解释、支持/猜测各自关系 | “与……相关”变“导致……”；删除作者保留的犹豫 |
| 专名和技术字面值 | 产品名、代码、接口、版本、命令、URL、受保护标题 | 为本地化改命令、拼写品牌新译名或替换真实链接 |

直接引用作为证据时保留原文；需要译文可在确有必要时注明是译文，不能在原引号内改写成更强说法。被讨论的措辞不是可随意清理的包装语。

## 术语合并

- 同一概念只用同一 `termId`，同一语言遵循 `termLedger` 的锁定拼写。英文名可原样保留；首次括注仅在读者确实需要、且解释有来源时使用，不强制每个术语双语展开。
- 当前用户明确术语选择优先于普通风格偏好；产品正式定义和作者锁定表达应显式保留。若用户要求与事实定义冲突，列 `term_conflict`，不要把错误翻译静默升级为正确概念，也不擅自推翻作者。
- 未知术语先保留原名并记候选译法；不能为了“更中文”发明已被认可的名称。上游公共词表只能提供候选，不是全局真理。
- 不对代码、URL、路径、API 枚举、原样引用做拼写美化。作品标题是否允许翻译由作者／产品层决定；作者固定英文标题不自动等于存在固定中文译标题。

## 中文和英文的自然表达

中文按意义组织短句，减少不承担关系的名词化和生硬语序；英文选择自然的动词和句序，避免逐字照搬中文修辞。两者都允许拆句、合句和调整指代，但必须保留同一主线、因果顺序及全部语义保护项。源文有自然的被动、反问、重复或技术术语时可以保留，不设禁词或句型命中数。

作者以工程事实解释产品时保持准确；作者的个人经历、立场和犹豫只有来源确实存在时才能沿用。不能靠虚构凌晨、客户对话、失败次数或感官细节制造“人味”。不将文风转换变成强迫自信或强制 CTA。

文化比喻能等义表达时可自然转换；转换可能改变对象、情绪或比较强度时，保留原义或记录歧义。补充解释只能解释已有定义，不得新增功能、收益、支持平台或操作步骤。保真与“像母语”冲突时保真优先。

图片中的文字和正文语言分开记录。已上传英文图用于中文稿时说明图中文字语言；不得称已本地化图片。本轮只更新配图 brief 所需语言／术语说明，图文事实共用 `claimIds`。

## 不增加审核轮次

翻译过程按以上约束直接完成，不单独产生母稿审核、平台审核、翻译审核和最终 polish。所有已选 `variantId` 的成稿备齐后，按照[一次审核与修订](audit-revision.md)对每份稿执行一次审核；其后统一修订。发现无法安全等义的地方记录 `unresolved`，不得用反复生成清零。

## 明确合成示例（非用户产品事实）

- 来源：`If the operator approves, our team may begin a pilot in November; production deployment has not been tested.` 自然中文：`如果操作负责人批准，我们的团队可能在 11 月开始试点；生产部署尚未测试。` 不可写成“我们将在 11 月上线”，因为它删除条件、扩大情态并改变完成状态。
- 来源：`This result does not show that the cache caused the improvement.` 自然中文：`这一结果并不能说明改善是缓存带来的。` 不可写成“缓存没有带来改善”，两句否定对象不同。
- 来源与作者表达均为英文、目标包含中英：英文平台稿在 `localize` 原样传递，中文从同一平台稿本地化；不先译中文母稿再回译英文。
